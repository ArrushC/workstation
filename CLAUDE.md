# CLAUDE.md

`workstation` is a self-contained dev-environment-provisioning system (mise: host provisioning + `[dotfiles]`) for Linux hosts + one Windows host.

**User-facing reference is `README.html`** (open in a browser from the repo root — loads `docs/README/README.css` + `docs/README/README.js`). The static developer console defaults to dark and supports light/system themes, passage search, keyboard navigation, platform quickstart tabs, category filtering with grid/list views, and troubleshooting controls; all documentation remains readable without JavaScript. When in doubt, point users at README.html sections rather than re-explaining them here.

This file is Claude-internal and deliberately kept lean (it loads into context every session). It carries the **rules and tripwires**; the verbose *why*, per-file gotchas, and verification recipes live in `docs/claude/` — pointers in "Claude-internal reference docs" below. When a tripwire fires (you're about to touch a listed area/file), read the matching doc before editing.

## Claude memory routing

Project-scoped memories (user/feedback/project/reference, per the standard `auto memory` taxonomy in the system prompt) live in **`.claude/memory/`** at the repo root — committed, code-reviewable, reproducible after a fresh clone. Write new memory files to `.claude/memory/<slug>.md` and update the index at `.claude/memory/MEMORY.md`. **Do NOT write to the home-dir memory path the system prompt suggests** (`~/.claude/projects/.../memory/`) — that path is intentionally left unsymlinked, so writes there would land outside source control and be invisible to other checkouts and reviewers. Escalate to a host-global memory location ONLY when the user explicitly asks for a memory to apply across all projects (and surface that scope choice in your reply so it's auditable).

## Before you change anything

The repo has a long history of regressions, and the load-bearing rules below were written in response to specific past breakage. Before editing a tricky area:

```bash
git log --oneline -- <path>            # prior fixes/reverts on this file
git log -p -S '<symbol>' -- <path>     # when a symbol was added/removed and why
git log --all --grep='<keyword>'       # search commit subjects (e.g. "crlf", "chmod", "preserve-env")
```

Also skim `CLAUDE_CHANGELOG.md` — the worked-examples archive of past user-facing changes and what README updates each required. If a change you're about to make rhymes with a row in that file, follow the same pattern.

If a fix smells like it could re-break a past pattern (CRLF endings, executable bits, sentinel blocks, which `MISE_ENV` token gates a config file), `git log` the affected file FIRST.

## Claude Code hooks (edit-time enforcement)

Hooks complement `check-invariants.sh` by moving enforcement to **edit time** and feeding it back to Claude. **Edit any hook → re-run `bash .claude/hooks/test-hooks.sh`** (asserts every decision). All parse hook JSON via `jq`→`python3`→fail-open; they emit compact JSON (PostToolUse `additionalContext`, exit 0; PreToolUse `permissionDecision` deny/ask). They're covered by `check-invariants.sh` (LF+0755 for `.claude/hooks/*.sh`, shellcheck for both sets). Cross-platform via Git-for-Windows bash (same precedent as `notify.sh`; needs `jq` on PATH or it fails open).

- **Repo** (`.claude/hooks/*.sh`, wired in `.claude/settings.json`, this repo only):
  - `post-edit-guard.sh` — PostToolUse; after you edit a run-directly `*.sh` (`scripts/*.sh` incl. `scripts/lib/*.sh`), a bare `tasks/*` script, `.githooks`, or a BOM `.ps1`, **auto-repairs** CRLF→LF, the +x/100755 mode, and the `.ps1` BOM, then says re-read.
  - `parity-reminder.sh` — PostToolUse; nudges the sibling on a parity/dual-edit (`dotfiles/zshrc.tera`↔`dotfiles/bashrc.tera`, the nushell `config.nu.tera`↔PowerShell `profile.ps1.tera` `ws*`/`g*` alias block, `manage-hosts.sh`↔`.ps1`, `python-env.sh`↔`bootstrap.ps1` `$PythonLibs`, `config.toml` `[vars]` host pins (three-way/triple dual-edits), `config.linux.toml`/`config.dev.toml` tool pins ↔ `bootstrap.ps1` `$PortableTools`/`MISE_VERSION`).
  - `memory-routing-guard.sh` — PreToolUse; **denies** writes to `~/.claude/projects/*/memory/` (the base prompt's suggestion), redirecting to `.claude/memory/`.
  - `sync-tool-memory.sh` — PostToolUse; on edits to `config.toml`/`config.*.toml` (tool `[tools]` tables, `[vars]` host pins, `[bootstrap.packages]` dnf keys), regenerates the `TOOLS` block in `dotfiles/claude/CLAUDE.md`; nudges to refresh `mise.lock` and run `wsa`.
  - `session-context.sh` — SessionStart (session-lifecycle, not edit-time); injects one compact `additionalContext` block of runtime facts: dotfiles deploy state (`mise dot status --json` — pending vs `$HOME` in sync), host identity + dev/prod group + EL family, WSL + **static** interop capability (probes `binfmt_misc/WSLInterop` + `command -v powershell.exe`, never spawns a Windows process), and guard-tool readiness (jq/shfmt/gitleaks/shellcheck + pre-commit). Each segment fail-opens independently; every external probe is `timeout`-bounded.
  - `session-end-notify.sh` — SessionEnd (session-lifecycle); when the repo is left with uncommitted changes and/or `mise dot status` reports entries not `applied` (and the end isn't a `/clear` or `resume`), fires a toast via the global `~/.claude/notify.sh`. The toast is fired **detached** (`setsid`, subshell fallback) so the hook returns instantly — a synchronous toast gets cancelled ("Hook cancelled") during SessionEnd shutdown. Emits no context (SessionEnd can't). `WORKSTATION_NOTIFY` overrides the notifier for the hook test.
- **Global** (`dotfiles/claude/hooks/*.sh` → `~/.claude/hooks/` via a `[dotfiles]` `copy` entry in `config.dev.toml`; enforced into `~/.claude/settings.json` by `scripts/lib/claude-settings-merge.sh` + `dotfiles/claude/settings.enforced.json`, all dev machines):
  - `secret-guard.sh` — PreToolUse; **denies** edit/read of SSH private keys, `*.pem`/`*.key`, and (defensively) a leftover pre-mise chezmoi age identity at `*/chezmoi/key.txt` if one still exists on a host (age/encryption itself was dropped, not ported — see ruling 9 below); **asks** on Bash naming them.
  - `dangerous-command-guard.sh` — PreToolUse; **denies** truly-never-legit Bash (fork bomb, `dd`/`>` raw device, `mkfs`, `chmod -R 777 /`); **asks** on recursive `rm -rf` of `/`|`~`|`$HOME`, `curl|bash`, force-push, recursive `chmod 777`. It matches command **text**, so a command that merely *mentions* a pattern (e.g. a commit message describing it) is screened too — reword or approve the prompt; that mention-matching is why the `rm -rf` tier is *ask*, not *deny*.

## Load-bearing invariants

README documents the *what*; these are the *why* and the failure modes. Each exists because the opposite was tried and broke. **One-line index below — full detail (failure stories, verify commands) in `docs/claude/invariants.md`. Read that file before acting on any entry you're about to touch.**

**Mechanical enforcement:** `scripts/check-invariants.sh` checks the mechanically-checkable subset of the invariants below (version-pin dual/triple-edits, the LF+0755 set, `.ps1` BOMs, unbraced `$name:` drive-lookalike refs in every tracked `.ps1` — PowerShell's parser reads `"$name:"` inside a double-quoted string/here-string as a drive-qualified variable and throws a parse error unless it's a real scope (`$env:`/`$script:`/…) or braced (`${name}:`) — sentinel-block matching, script-flag↔completion parity, bumper-EXCLUDE coverage of every dual-edit pin, and every `[dotfiles]` table across `config.toml`/`config.linux.toml`/`config.dev.toml`/`config.host.toml`/`config.windows.toml` — `check_dotfiles_config`: every entry's `source` exists, every `mode` is one of mise's `symlink`/`symlink-each`/`copy`/`template`/`track` schema values, no entry in any of the five files actually IS `symlink`/`symlink-each` — ruling 7, broadened by the 2026-09-22 copy-migration from "never on Windows" to "never anywhere" — every directory entry with an `exclude` list covers every `.vendor`/`.gitkeep` sidecar present in its source, and every `dotfiles/**/*.tera` file is referenced by exactly one entry) and runs shellcheck at warning+, `shfmt -i 2` formatting, and a `gitleaks` committed-secret scan over the first-party shell set (CI installs both from `config.linux.toml` via `jdx/mise-action` so they enforce there too — with `MISE_LOCKFILE=false`, because a non-`$HOME/.config/mise` config root makes `mise install` rewrite the lock sidecar refs; see `docs/claude/file-care.md`). `scripts/check-templates.sh` renders every `dotfiles/**/*.tera` file (11 total) individually, for each of the four real `MISE_ENV` token sets, into a scratch `$HOME`, syntax-checks the output (zsh/bash/gitconfig/nu/pwsh + yq for YAML + python3 tomllib for TOML; soft-skips missing checkers locally, the lint.yml `templates` job enforces the full set in CI), THEN does one bulk `mise bootstrap --only dotfiles --force-dotfiles --yes` per token set and re-checks — because one broken template aborts the WHOLE apply (ruling 3), the individual pass is what names the culprit. Run it via `mise run lint`, install it as a pre-commit hook via `mise run install-hooks`, or let CI (`.github/workflows/lint.yml`) run it. **When you add a new invariant of one of these shapes, add a check there too.** PowerShell scripts are linted by PSScriptAnalyzer (`scripts/check-ps.ps1` / `PSScriptAnalyzerSettings.psd1`) in the same CI workflow; run locally with `mise run ps-lint`. `scripts/check-readme.mjs` drives `README.html` + `docs/README/README.js` under jsdom (CI `readme` job; locally `npm install --no-save --no-package-lock jsdom@30.0.1 && node scripts/check-readme.mjs`; `node_modules/` is gitignored) — search titles without the injected chip count, filters surviving in-page anchor clicks, one navigation per Back — the 2026-09 console redesign shipped with all three broken. A weekly `version-bumps.yml` workflow runs `scripts/bump-versions.sh` (`mise run bump-versions`), which bumps mise tool pins via `mise outdated --bump` + `mise config set` + refreshed lockfiles and PRs any drifted single-location `config.toml` `[vars]` pin (the dual/triple-edit pins — `python_version`, `nerd_font_version` — are reported, not auto-edited; a new dual-edit pin MUST join the script's `EXCLUDE` list, and `check-invariants.sh` asserts this by deriving the pin set from its own `check_version_pins` — the gap that failed version-bumps run #9).

- **`bootstrap.sh` is a thin seed** — no `*_VERSION`/install logic beyond the one exception (`MISE_VERSION`/`MISE_SHA256`, the pinned mise binary it sha256-verifies into `~/.local/bin` before handing off); everything else lives in `config*.toml` (`[bootstrap.*]`/`[dotfiles]` tables) or `tasks/`. It installs pinned mise, computes `MISE_ENV` from `--dev`/`--prod` (`scripts/lib/mise-env.sh` is the single source of the token sets), runs `scripts/lib/mise-install.sh` (tools, ahead of `mise bootstrap` — Ruling 7: its node-postinstall-marker logic has no mise equivalent, so `mise bootstrap`'s own tools phase is then a no-op), then `mise bootstrap --yes` (packages, files, services, compose, repos, dotfiles, tools gate, then the `bootstrap` task).
- **`MISE_ENV` tokens pick which config files load** — `config.toml` (always) · `config.linux.toml` (`linux`) · `config.dev.toml` (`dev`) · `config.host.toml` (`host` — dnf packages + the EPEL/CRB `pre-packages` hook, PLUS the Linux-dev-only dotfiles: `~/.gdbinit`, `~/.config/gdb`, `~/.config/herdr/config.toml`) · `config.native.toml` (`native` — NFS client) · `config.wsl.toml` (`wsl` — `/etc/wsl.conf`) · `config.windows.toml` (`windows` — the 13 Windows-only dotfiles) · `config.local.toml` (always, git-ignored). Token sets: prod `linux`; dev WSL `linux,dev,host,wsl`; dev native `linux,dev,host,native`; Windows `windows,dev`. **Prod hosts load no host state** — `config.host.toml`/`config.native.toml`/`config.wsl.toml` carry every sudo-requiring table; never add one to `config.toml`/`config.linux.toml`/`config.dev.toml`.
- **`[bootstrap.*]` tables merge by union across every loaded config file** (verified) — a dnf package, an `/etc` file, or a service can be declared in whichever file's `MISE_ENV` token gates it; don't duplicate a declaration across files to "be safe". `config.host.toml`/`config.native.toml`/`config.wsl.toml` declare NO `[tools]` (lock coverage stays exactly `mise.lock`/`mise.linux.lock`/`mise.dev.lock`).
- **Hooks are always `mise run <task>`** — hook strings are opaque shell to mise (no verified cwd/PATH/`$HOME` expansion); `mise run` finds global tasks from any cwd and puts tools on PATH. Every hook name is defined in exactly ONE config file (merge semantics for a duplicate hook name are unverified — don't rely on them). Tasks live in `$HOME/.config/mise/tasks` (i.e. this checkout) and are **not redirectable by `MISE_CONFIG_DIR`** — mise always discovers global tasks from the real home, even when a test or CI run points `MISE_CONFIG_DIR` elsewhere (`scripts/check-templates.sh`'s own header documents and works around the matching global-CONFIG-discovery fallback for `mise dot`/`mise bootstrap`). Task names must not collide with a mise built-in for shorthand use — `mise fmt` is a mise built-in, so ours is `mise run fmt`. `post-dotfiles` is the one exception to "always `mise run <task>`" — it's a pinned, verified-safe literal shell one-liner (see the dotfiles-hooks entry below), not a task reference.
- **dnf packages are all-or-nothing** — mise runs ONE `sudo dnf install -y <every missing name>` per `[bootstrap.packages]` table; a single unresolvable name fails the WHOLE batch. Every name in `config.host.toml`/`config.native.toml` is EL9-verified (spike table, 2026-09-17) — never add a name the spike marked NOT FOUND or virtual. Three names Make used to install are gone: `fswatch`, `entr` (not packaged for EL9), `cockpit-networkmanager` (a virtual provide of `cockpit-system`, never satisfiable by `rpm -q`). `ShellCheck` is capitalised — EPEL ships it that way. `make` itself STAYS in the dnf list (Ruling 5) — it's a C-toolchain dependency now (`bear -- make`, autotools), not our orchestrator.
- **No `[bootstrap.linux.firewall]` table, anywhere** (Ruling 1) — any firewall rule makes mise re-exec itself with sudo for `mise bootstrap plan`/`status` too, which then aborts unprivileged (`sudo requires a password but no TTY`) and would break `mise run health` on every host. (Discovered opening Cockpit's port via a `post-packages` hook task; Cockpit provisioning was removed entirely 2026-09-22 — see `CLAUDE_CHANGELOG.md` — but the invariant still applies to any future `[bootstrap.*]` table that would need one.)
- **No `[bootstrap.user] login_shell`** (Ruling 2) — it shells out to `chsh`, which EL9 minimal images don't ship (`util-linux-user`) and which prompts for the user's password. `bootstrap.sh`'s `set_default_shell()` (sudo `usermod` on dev, printed `chsh` hint on prod) stays the only mechanism.
- **Pins Make used to own live in `config.toml` `[vars]`** — `python_version` (== `tools.python` == `bootstrap.ps1` `$PythonEnvVersion`, three-way), `nerd_font_version` (== `scripts/lib/font.sh` SHA arm == `scripts/install-nerd-fonts.ps1` `$Version`, triple), `vcpkg_version`, `zjstatus_zellij_floor`. Tasks read them via `#MISE env={NAME="{{ vars.name }}"}` (Tera rendering, spec-verified). Never hand-edit `mise*.lock` or anything under `locks/**` (regenerate with `mise lock --global` from outside the checkout via the `XDG_CONFIG_HOME` symlink form, then normalize the sidecar paths — see `docs/claude/file-care.md`'s lock-files entry and `scripts/bump-versions.sh`). Because the checkout IS `~/.config/mise`, running `mise use -g …`, `mise settings set …`, `mise bootstrap`, `wse`, or `mise dot add`/`wsr` writing a captured source file back all write straight to these TRACKED files — commit or revert them before moving on, never leave the checkout dirty (`update-hosts.sh` pulls `--ff-only`, which fails against local changes; `mise run health` has a dedicated "repo checkout" row for it). Ruling 8 — "a symlinked dotfile edited in place dirties the repo" — is RETIRED by the 2026-09-22 copy-migration: every deployed file is now an independent `copy`/`template` under `$HOME`, not a symlink into this checkout, so editing a DEPLOYED file (e.g. `~/.claude/CLAUDE.md`) no longer touches the repo at all — see the `[dotfiles]` bullet below for what replaced it (drift that `wsa` can silently overwrite, and the `wsr`/`mise dot add` round-trip that's now the only way back).
- **Post-tools `tasks/verify-tools` gate** — after `scripts/lib/mise-install.sh` runs `mise install` (once directly from `bootstrap.sh`, ahead of `mise bootstrap`; a no-op the second time when `mise bootstrap`'s own tools phase re-runs it), `config.linux.toml`'s `post-tools` hook (`mise run verify-tools`) hands off to `scripts/lib/verify-binary.sh` over every ELF binary `mise bin-paths` exposes, failing the install loudly if one can't run on this host — no silent "installed but won't run" (the original motivation: fastfetch's musl loader + usql's glibc floor). Non-executing: ELF+arch → `ldd` (static→PASS; `not found`→FAIL) → glibc-floor. **Static binaries MUST pass** — don't "tighten" the check to fail non-dynamic binaries; it would false-fail the many musl tools. Symlinked bins (mise's `.mise-bins/` indirection) are followed, not skipped. This is a **post-install** gate over everything mise just installed, not a pre-stamp gate per tool — a failure means picking an explicit `github:` `asset_pattern` for that tool in `config*.toml`. Full detail + verify recipe in `docs/claude/invariants.md`.
- **`[dotfiles]` entries, mode per class, no exceptions without a comment saying why** — `template` for the 11 `.tera` sources (Tera templating; ruling 3: ONE undefined variable or failing `exec()` in ANY template entry aborts the ENTIRE `mise dot apply`/`mise bootstrap` and writes NOTHING — every template needs an `is defined` guard or `default()` on each `vars.*` reference); `copy` for EVERYTHING else, on every platform (ruling 7, broadened by the 2026-09-22 copy-migration — user decision: chezmoi's copy semantics survive applications on either OS that don't respect symlinks. Before that, only Windows-loaded entries were forced onto `copy` — Windows file symlinks need Developer Mode and silently fall back to copy, `symlink-each` always copied there anyway, a directory symlink becomes a junction — now `symlink`/`symlink-each` are retired everywhere, Linux included, for the same underlying reason). A directory source keeps `exclude = [".vendor", ".gitkeep"]` on its `copy` entry — verified for the migration that `copy` on a directory does NOT wholesale-replace it the way a directory `symlink` does (C2, final-fix-brief.md): it copies in only the tracked files and leaves unmanaged siblings alone, same guarantee `symlink-each` used to give. **Deployed files no longer live inside this checkout** — ruling 8 ("editing a symlinked dotfile dirties the repo") is RETIRED; a live edit under `$HOME` is now an independent copy that (a) does NOT dirty the repo and (b) does NOT round-trip back to `dotfiles/` on its own. Getting it back into the repo needs an explicit step: `wsr` (`mise dot add --changed`) for a FILE-mode entry, but **`--changed` skips directory-mode entries entirely** (PR3 spike finding, reconfirmed 2026-09-22) — for a directory entry (`~/.claude/agents`, `~/.claude/commands`, `~/.claude/hooks`, `~/.claude/skills`, `~/.config/zellij`, `~/.config/zsh/completions`, `~/.config/gdb`, `~/.local/bin`) you must name the directory's exact target path, `mise dot add <that directory>` — naming an individual file INSIDE a directory entry errors with a conflicting-declaration message instead of updating it. `mise dot add <dir>` captures both edits AND brand-new files added directly under $HOME, but it's a REPLACE of the source directory's contents, not a merge — a source-only placeholder like `.gitkeep` that was never deployed (excluded) will be silently dropped from the source the first time you do this, which is fine once the directory has real tracked content. The other genuine behavior loss versus chezmoi: **copy-mode `mise dot apply` silently overwrites an un-recorded live edit** — no `--force`, no diff, no warning; chezmoi prompted here. `wsa` (the `mise bootstrap --only dotfiles --yes` alias, now a function in `dotfiles/{bashrc,zshrc}.tera` + the Windows nu/PS1 profiles) checks `mise dot status --json` for any entry in `differs` state first, shows `mise dot diff` for it, and asks before proceeding (refuses outright, non-interactively) — this is what stands between an un-recorded `~/.claude/CLAUDE.md` edit (which Claude Code agents are routinely nudged to make directly) and silently losing it on the next `wsa`; a bare `mise bootstrap --only dotfiles --yes` still overwrites silently, by design, for scripted/CI use. Disabling an entry inherited from a less-specific config file needs `enabled = false` **AND** a repeated `mode` in the override (ruling 2) — `enabled = false` alone is silently ignored; this is how `scripts/setup-ccstatusline.sh`'s per-host opt-out (written into `config.local.toml`'s own `[dotfiles]` table) works. **First apply on a host still running the old chezmoi bootstrap needs `--force-dotfiles`** (ruling 1) — every target already exists as a real file (chezmoi's own deploy), and `copy`/`template` refuse to overwrite one that already differs (even `--dry-run` exits 1). `bootstrap.sh`/`bootstrap.ps1` pass it automatically, but ONLY while `~/.local/state/workstation/dotfiles-migrated` is absent, so a later real conflict still fails loudly instead of being silently reclaimed.
- **Every `ws*` command pins `mise -C` to the host's own home directory** (`$HOME` Linux, `$env:USERPROFILE`/`$env.USERPROFILE` Windows) — mise resolves its config root by walking UP from the current directory, and this checkout IS `~/.config/mise`, so an unpinned run from anywhere with its own `.config/mise` reachable in that walk (a Windows drive mount under WSL, a second checkout, or a WSL-exposed `\\wsl$\...` path from Windows) silently manages the WRONG checkout instead of erroring — confirmed live 2026-09-22: an unpinned `wsa` from `/mnt/c/Users/<user>` rewrote `~/.zshrc`/`~/.bashrc` from a stale clone and made seven dotfiles executable. `wsa` additionally probes `mise dot status --json`'s `.files[0].origin.config_root` and refuses to apply if it isn't exactly the pinned root (proceeds if the probe can't determine it — a false-positive guard is worse than none). `wsu` is pinned too — `tasks/update`'s own `root` is derived from `$0`'s resolved on-disk location, which follows the same cwd-walked config root, so leaving it unpinned reproduces the identical wrong-checkout bug via `git pull` + `mise bootstrap` instead of just a read.
- **`post-dotfiles` bootstrap hook restores the directory modes `copy`/`template` can't express** — `chmod 700 ~/.ssh ~/.claude 2>/dev/null || true; chmod 600 ~/.ssh/config 2>/dev/null || true` in `config.linux.toml`. `template`/`copy` propagate the SOURCE file's own on-disk bits, and git tracks only the executable bit, so a fresh clone's `dotfiles/ssh/config.tera` is 0644 and the directories land at default mode — this hook is the ONLY guarantee of the SSH/Claude security posture. Each command carries its own `|| true` (not one trailing `; true`) because mise runs bootstrap hooks under `sh -o errexit`, and a missing `~/.claude` on a prod host (no `config.dev.toml`) would otherwise abort the chain before `~/.ssh/config`'s chmod ever ran.
- **`~/.claude/settings.json` is NOT a `[dotfiles]` entry** (ruling 5 — mise has no `modify_`-template equivalent) — `scripts/lib/claude-settings-merge.sh` (jq), run from `tasks/bootstrap` (Linux) / `bootstrap.ps1`'s `Invoke-ClaudeSettingsMerge` (Windows, same jq filter — I3), deep-merges three layers, later winning: `dotfiles/claude/settings.seed.json` (personal defaults, set only when the corresponding key is ABSENT from the live file) → the live `~/.claude/settings.json` → `dotfiles/claude/settings.enforced.json` (infra keys that ALWAYS win: `statusLine`, `hooks`, `enabledPlugins`, `skipAutoPermissionPrompt`, `skipWorkflowUsageWarning`, `remoteControlAtStartup`, `agentPushNotifEnabled`, `inputNeededNotifEnabled`). The merge is jq's recursive `.[0] * .[1] * .[2]` (matches chezmoi's old `mergeOverwrite`): a later operand overwrites a matching LEAF, but a live-only sibling key (e.g. a hand-added `hooks.Stop`) survives. Soft-failing by design (no jq / missing source / invalid existing JSON / write failure → warn to stderr, exit 0); writes atomically (temp file + `mv`, mode 0600). `settings.local.json` also stays out of `[dotfiles]` — Claude Code rewrites it wholesale on every run. To change an enforced key cross-host, edit `dotfiles/claude/settings.enforced.json`.
- **The dev-gate asymmetry chezmoi had is fixed by construction** (ruling 10) — chezmoi's old ignore block listed only Linux-form paths for the dev-only gate, so a hypothetical Windows prod host would have deployed `~/.claude` ungated. Dev-only dotfiles now live in `config.dev.toml` (or `config.host.toml` for Linux-dev-only ones), gated purely by the `dev`/`host` `MISE_ENV` tokens on BOTH OSes — no separate `group`/ignore-list mechanism exists any more. `config.local.toml` (git-ignored, per-host) carries only `[vars] name`/`email` now (migrated once from a legacy `~/.config/chezmoi/chezmoi.toml` if present, else prompted interactively via `/dev/tty` — see `ensure_config_local()` in `bootstrap.sh`, load-bearing under `curl | bash` the same way the old chezmoi-init prompt was) plus any per-host `[dotfiles]` override (e.g. the ccstatusline opt-out above).
- **WSL detection centralized in `is_wsl()`** in `bootstrap.sh` — extend the helper, don't fork detection.
- **`dotfiles/` is the whole source tree, real names, no equivalent of `.chezmoiroot`/`dot_`/`private_` prefixing** — each `[dotfiles]` entry's `source =` path is relative to the repo root and names the file directly (`dotfiles/zshrc.tera`, not `dot_zshrc.tmpl`). age/encryption support was dropped entirely, not ported (ruling 9) — zero `encrypted_*` files existed, `bootstrap.sh`'s old `check_age_identity`/`WORKSTATION_AGE_RECIPIENT` plumbing is gone; `secret-guard.sh` keeps a defensive check for a leftover `chezmoi/key.txt` purely in case one lingers on an unmigrated host.
- **Only two valid host groups** — `dev_machine`/`prod_machine`; both manage-hosts scripts reject others. A third needs `scripts/lib/mise-env.sh` (a new `MISE_ENV` token set) AND `update-hosts.sh` changes.
- **`configs/` is deployed to `/etc/` via `[bootstrap.files]` (+ `[bootstrap.services]` when a deployed file needs to restart something), NOT a `[dotfiles]` entry** — `[dotfiles]` owns `$HOME` only. `source` paths are relative to the repo root; there is no `sudo` key on a `[bootstrap.files]` entry — mise elevates itself; `phase` is only `pre-packages`/`post-packages`. The only current user is **`/etc/wsl.conf`**: `config.wsl.toml`'s `[bootstrap.files]` entry, gated purely by the `wsl` `MISE_ENV` token (no separate `IS_WSL`/`HAS_SUDO` check needed — the file only loads on WSL dev hosts at all) and still carries `appendWindowsPath=false`. Its Windows counterpart is unchanged: the global `%USERPROFILE%\.wslconfig` is a `[dotfiles]` `copy`-mode entry in `config.windows.toml` (source `dotfiles/wslconfig`, declared only there so it deploys only on Windows — no separate ignore-list needed); mise has no `run_onchange` equivalent (ruling 6), so a `bootstrap.ps1` step sha256-compares the source against a stored marker and prints a `wsl --shutdown` reminder on change — there is no equivalent reminder on the Linux side. **Docker/Cockpit/rsyslog/Dozzle provisioning (`config.native.toml`'s old `[bootstrap.files]`/`[bootstrap.services]`/`[bootstrap.compose]` entries, `configs/docker,cockpit,rsyslog,dozzle/`) was removed entirely 2026-09-22** (user decision — see `CLAUDE_CHANGELOG.md`): mise no longer installs or configures any of the four; hosts that already had them keep them, unmanaged, and nothing here updates them any more. Full detail in `docs/claude/file-care.md`.
- **SSH multiplexing is gated out on Windows** — the `ControlMaster`/`ControlPersist`/`ControlPath` block in `dotfiles/ssh/config.tera` sits under `{% if os() != "windows" %}`. Windows OpenSSH can't multiplex (breaks every ssh incl. git). Linux/macOS keep it.
- **zsh interactive plugin load order** — in `dotfiles/zshrc.tera`: fzf-tab after `compinit` → zsh-autosuggestions → zsh-syntax-highlighting → **zsh-history-substring-search LAST** (it must come *after* syntax-highlighting, per upstream; then ↑/↓ are bound to its widgets). syntax-highlighting must still see all earlier widgets (incl. shift-select). zsh-you-should-use is a preexec hook (order-loose). Reorder → highlighting/suggestions/history-nav silently break. fzf-tab needs `use-fzf-default-opts yes` to inherit the Catppuccin `FZF_DEFAULT_OPTS`. Keymap: `Ctrl-R`=atuin (wired with `--disable-up-arrow` so ↑/↓ stay free), ↑/↓=substring-search, →=autosuggest, `Tab`=fzf-tab. All five plugins are zsh-only — `dotfiles/bashrc.tera` carries PARITY NOTEs (readline `history-search-*` on ↑/↓ as the substring-search analog; atuin + you-should-use have no bash counterpart). atuin/broot(`br`)/yazi(`y`) are wired tools, not plugins; broot+yazi in both shells, atuin zsh-only (bash needs bash-preexec). `~/.zshenv` (`dotfiles/zshenv.tera`, `config.linux.toml` — Linux-only by construction, since Windows never loads that config file) carries only two guarded PATH prepends — `~/.local/bin` (preserving what the host's pre-chezmoi `.zshenv` provided) and the mise shims — keep it tiny, it runs for every zsh. `MISE_ENV` is computed identically (a byte-identical Tera conditional) in `dotfiles/zshenv.tera`, `dotfiles/bashrc.tera`, AND `dotfiles/config/environment.d/10-mise.conf.tera` — a triple-edit, verified by `check-invariants.sh`'s `check_mise_env_three_way`.

## Conventions and rules of thumb

- **Don't fixed-width-pad `hosts.conf`** — manage-hosts re-pads on every save.
- **`scripts/manage-hosts.sh` and `scripts/manage-hosts.ps1` are a parity pair.** Every user-visible capability (flags, menu options, prompts, defaults, post-add flow, output glyphs) must exist in both. Change them in the same commit. Drift silently breaks Linux/Windows reproducibility.
- **All tool installs are mise pins in `config.toml`/`config.linux.toml`/`config.dev.toml`; all host state is `[bootstrap.*]` tables in `config.host.toml`/`config.native.toml`/`config.wsl.toml`; all dotfiles are `[dotfiles]` entries** — never re-introduce per-tool install logic or a shell-scripted provisioning step in `bootstrap.sh`, a new `scripts/*.sh`, or a new playbook; procedural steps are global mise tasks under `tasks/`.
- **Per-machine overrides go in `~/.zshrc.local`** (Linux, sourced from `dotfiles/zshrc.tera`; `~/.bashrc.local` still works if you've started an interactive bash) / `Microsoft.PowerShell_profile.local.ps1` (Windows) / `~/.ssh/config.local` (both). Un-tracked, sourced/included last.
- **After editing any file under `scripts/` or `tasks/`** (shell side): verify with `file <path>` (must NOT say "with CRLF line terminators") and `git ls-files --stage <path>` (must show `100755` for the lib scripts / every `tasks/*` file — mise silently skips a non-executable file task). Repairs: `sed -i 's/\r$//' <path>` and `git update-index --chmod=+x <path>`.
- **After editing `scripts/manage-hosts.ps1` or `bootstrap.ps1`**: verify they retain UTF-8 BOM. PowerShell 5.1 mis-decodes UTF-8 glyphs (`✓`, `✗`, `─`) without one and fails to parse. Restore with `[System.IO.File]::WriteAllText($path, ..., [System.Text.UTF8Encoding]::new($true))`.
- **When changing user-facing surface, update `README.html` (and `docs/README/README.css` / `docs/README/README.js` if needed) in the same commit, then append a row to `CLAUDE_CHANGELOG.md`.** Decision test: "Would a user reading only `README.html` still be able to operate this repo after my change?" If no, README needs an update.

What does NOT need a README update: internal `tasks/*`/`scripts/*` refactors that don't change CLI overrides or file locations; comment edits / formatting / variable renames invisible outside them; bumping a tool version (lives in `config*.toml`, or in `config.toml`'s `[vars]` for the pins Make used to own); edits to Claude-internal files (this `CLAUDE.md`, `docs/claude/*`, `.claude/`).

## Files Claude should be careful with

Per-file gotchas live in **`docs/claude/file-care.md`** — read a file's entry before editing it. The cross-cutting risk categories (the tripwires):

- **LF-only + mode 100755 in git:** `scripts/*.sh` (incl. `scripts/lib/*.sh` — `mise-env.sh`, `mise-install.sh`, `verify-binary.sh`, `zellij-plugin.sh`, `enable-el-repos.sh`, `font.sh`, `python-env.sh`, `vcpkg.sh`, `check-updates.sh`, `claude-settings-merge.sh`), every file under `tasks/` (the global mise tasks — `bootstrap`, `health`, `check-updates`, `update`, `update-hosts`, `python-env`, `fonts`, `vcpkg`, `lint`, `fmt`, `ps-lint`, `secrets`, `install-hooks`, `inventory`, `bump-versions`, `statusline`, plus the hidden install-time helpers `enable-el-repos`, `verify-tools`, `migrate-legacy`), `.claude/hooks/*.sh`, and the executable `dotfiles/**` sources (`dotfiles/claude/hooks/*.sh`, `dotfiles/claude/notify.sh`, `dotfiles/local/bin/*`) whose `copy` mode propagates the source file's own git-tracked executable bit. CRLF or mode 100644 breaks fresh clones (`sudo: archive.sh: command not found`) — for `tasks/*` specifically, a non-executable or CRLF file makes mise silently skip it as a discovered task. Repair one-liners in Conventions above. **First-party shell edits must also be `shfmt -i 2`-clean and pass a `gitleaks` scan** — `check-invariants.sh` enforces both (pre-commit + CI); `mise run fmt` auto-formats. `shfmt -w` preserves mode, but re-verify LF+0755 after a bulk format.
- **Converse: every OTHER tracked `dotfiles/` source must be git mode `100644`** — `check-invariants.sh`'s `check_dotfiles_mode` allowlists exactly the five files above (`git ls-files -s dotfiles/ | grep 100755` to reproduce) and fails on any other 100755, `.tera` template sources especially: `template`/`copy` both propagate the source's own executable bit onto `$HOME`, and on a filesystem that reports every file 0744 regardless of git mode (DrvFs over a Windows drive mount) that propagation becomes an invisible `chmod +x` across every managed dotfile the moment `wsa` runs — this is exactly how `~/.gitconfig`/`~/.bashrc`/`~/.zshrc`/`~/.zshenv`/`~/.config/cheat/conf.yml`/`~/.config/environment.d/10-mise.conf`/`~/.gdbinit` went executable on 2026-09-22. Add a new executable dotfile to the allowlist deliberately, in the same commit.
- **UTF-8 with BOM (PowerShell 5.1):** `scripts/manage-hosts.ps1`, `bootstrap.ps1`, `scripts/install-nerd-fonts.ps1`. Restore one-liner in Conventions above.
- **Vendored — don't hand-edit; re-download at the pinned tag + refresh sha256:** `dotfiles/config/zsh/plugins/zsh-shift-select.zsh`, `dotfiles/config/zsh/completions/_cht.sh` (rolling — no upstream tag; bump by snapshot date + sha256, `#compdef cht.sh` stays line 1).
