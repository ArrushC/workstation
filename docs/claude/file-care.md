- **`chezmoi/dot_config/wezterm/` (modular WezTerm config, 2026-07 split)** — `wezterm.lua` is the ENTRY POINT only: it prepends its own directory to `package.path` (**load-bearing on Windows** — WezTerm 20240203 doesn't search the config file's dir, and `~/.config/wezterm` doesn't exist there since `WEZTERM_CONFIG_FILE` points into the repo; remove it and every sibling `require` breaks) then applies `appearance` → `domains` → `wsl` → `tabs` → `status` → `actions` → `keys` in dependency order (later modules read earlier modules' exports — don't reorder). **`hosts.lua` carries the auto-gen'd `-- HOSTS:START/END` SSH-domains block** (sentinels at column 0 — manage-hosts.sh's awk anchors `^-- HOSTS:START`); edit anywhere outside it freely. On Windows, edits to ANY module propagate to WezTerm immediately via `WEZTERM_CONFIG_FILE` + the require-watch; the dir is chezmoi-ignored on every OS (`.config/wezterm` target-path entries in both ignore blocks — Linux hosts run no WezTerm), so it lives in the repo only.
- **`chezmoi/dot_dircolors`** — Catppuccin Mocha `LS_COLORS` database (GNU `dircolors -p` default recolored to truecolor), eval'd by both shell rc files. The explicit `TERM wezterm` capability-gate line is load-bearing: hosts run `TERM=wezterm` (see the `config.term='wezterm'` invariant in `docs/claude/invariants.md`), which matches NONE of the GNU default `TERM` globs, and `dircolors` only emits `LS_COLORS` when a `TERM` directive matches `$TERM`. Drop `TERM wezterm` and listings lose all color under `TERM=wezterm`. The db also carries `COLORTERM ?*`, but it does NOT rescue an unmatched `TERM` (verified on coreutils 8.32: `TERM=dumb COLORTERM=truecolor` still yields an empty `LS_COLORS`) — it's kept only as a harmless secondary catch-all for newer coreutils, never relied upon. Static, LF-only, applies to all Linux hosts (not behind the dev gate); Windows-ignored.
- **`chezmoi/dot_local/share/wezterm/wezterm.terminfo`** — vendored from wezterm/wezterm upstream at a pinned release tag (recorded in the file's leading `#` comment). Editing this file by hand defeats the vendoring contract; it is refreshed automatically by `.github/workflows/wezterm-nightly.yml` when upstream main drifts (provenance header records the upstream commit + snapshot date). Manual fallback: re-download from https://raw.githubusercontent.com/wez/wezterm/<commit>/termwiz/data/wezterm.terminfo and keep the 2-line provenance header shape (the workflow's cmp skips those 2 lines). The pair `chezmoi/.chezmoiscripts/run_install-wezterm-terminfo.sh.tmpl` re-tic's it into `~/.terminfo/` on every `cza` (it self-heals — see its entry below).
- **`chezmoi/.chezmoiscripts/run_install-wezterm-terminfo.sh.tmpl`** — Linux-only via the body `{{ if eq .chezmoi.os "linux" }}…{{ end }}` gate (`.chezmoiscripts/` are not in `.chezmoiignore`). A **`run_` (every-apply) script, NOT `run_onchange_`** — it self-heals: it re-tic's whenever ncurses can't resolve `wezterm` (entry missing) OR the vendored source changed since the last compile (tracked by a `~/.terminfo/.wezterm.srchash` stamp of the source sha256), and no-ops cheaply otherwise. **Don't revert it to `run_onchange_`:** that records the soft-fail skip (ncurses not yet installed) as a successful run and then never retries until the source bumps, which is exactly the regression this fixed — full failure story in `docs/claude/invariants.md` (terminfo chain). Soft-fails with `exit 0` if `tic` or the source file are missing — `cza` is daily-workflow and shouldn't gain a new failure mode just from missing ncurses. The `tic -x` flag preserves `Tc`/`Smulx`/`Setulc`; dropping it silently degrades capability advertising.
