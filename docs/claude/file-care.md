- **`chezmoi/dot_dircolors`** — Catppuccin Mocha `LS_COLORS` database (GNU `dircolors -p` default recolored to truecolor), eval'd by both shell rc files. `dircolors` only emits `LS_COLORS` when a `TERM` directive matches `$TERM` — the fleet's `TERM=xterm-256color` (Windows Terminal) and the multiplexer TERMs are covered by the stock globs (`xterm*`, `screen*`, `tmux*`); don't prune those directives, and any future custom `TERM` needs its own line or listings silently lose all color. The db also carries `COLORTERM ?*`, but it does NOT rescue an unmatched `TERM` (verified on coreutils 8.32: `TERM=dumb COLORTERM=truecolor` still yields an empty `LS_COLORS`) — it's kept only as a harmless secondary catch-all for newer coreutils, never relied upon. Static, LF-only, applies to all Linux hosts (not behind the dev gate); Windows-ignored.
- **`chezmoi/dot_config/zsh/plugins/zsh-shift-select.zsh`** — vendored from `jirutka/zsh-shift-select` at a pinned tag (recorded in the file's leading `#` header: tag `v0.1.1`, commit, upstream sha256). MIT, single file, zero deps. Provides the `shift-select` ZLE keymap + Shift+Arrow selection widgets at the prompt. Static (no `.tmpl`), **LF-only**, deploys on BOTH dev and prod (a general shell nicety, not behind the `.chezmoiignore.tmpl` dev gate); Windows-ignored via the `.config/zsh` line in the Windows block. Editing this file by hand defeats the vendoring contract — bump by re-downloading the pinned tag, refreshing the sha256, and updating the header. Sourced (and supplemented) by `dot_zshrc.tmpl`.

Static (no `.tmpl`), **LF-only**, deploys on BOTH dev and prod; Windows-ignored via the `.config/zsh` line in the `.chezmoiignore.tmpl` Windows block. Autoloaded because `dot_zshrc.tmpl` prepends `~/.config/zsh/completions` to `$fpath` *before* `compinit`. - **`makefile/Makefile` and `tools.mk`** — recipe lines must be tab-indented. Macro bodies use `$$` for deferred expansion. `EGET_TOOL` adds an order-only dep on the eget stamp, not the phony — preserve under any refactor or parallel builds will race. The tool macros also self-register the doctor/check-updates rows (`DOCTOR_ROWS` from all three macros; `UPDATE_SPECS` from `EGET_TOOL` only) — **adding a `TOOL`/`USER_TOOL` entry (or a new bespoke pin in `versions.mk`) requires a matching hand line in the UPDATE-CHECK REGISTRY block at the bottom of `tools.mk`**, or `make check-updates` silently omits it; a new bespoke Makefile target likewise needs a `DOCTOR_ROWS += bespoke|…` line next to the `doctor` target AND a case branch in `lib/doctor.sh`. The rows contain `|`, so in the `doctor`/`check-updates` recipes they MUST stay single-quoted via `$(foreach …,'…')` — unquoted, the shell parses every row as a pipeline and *executes the tool names* (this happened; see `git log`).
- **`makefile/scope.mk`** — single source for `MODE` → `DEST` / `SUDO` / `HAS_SUDO` / `INSTALL_PACKAGES`. Parse-time error on missing MODE is intentional.
- **`makefile/{packages,shell,dotfiles}.mk`** — `packages.mk` is a no-op when `INSTALL_PACKAGES=false`. `shell.mk` branches on `HAS_SUDO`. `dotfiles.mk` is gated on `~/.config/chezmoi/chezmoi.toml` existing (first-run init is `bootstrap.sh`'s job).
- **`makefile/versions.mk`** — single source for tool versions. `EGET_VERSION` pins the meta-installer itself; bumping it triggers a fresh eget install via `archive.sh`, which then runs every `EGET_TOOL` install.
- **`makefile/lib/eget.sh`** — bakes in `--to $DEST --quiet` plus an asset anti-match filter (`.sbom .sig .sha .b3 .asc .zip.gpg .deb .rpm .apk .pkg .proof`). When upstream adds a new noise file type that breaks auto-detection, add it here, not per-tool. (`.b3` = cargo-dist's BLAKE3 per-asset checksum, e.g. watchexec's `…-musl.tar.xz.b3`, which otherwise collides with the real tarball under `--asset musl`.)
- **`makefile/lib/*.sh` and `scripts/update-hosts.sh`** — must be LF-only AND mode 100755 in git. A fresh clone with mode 100644 fails with `sudo: archive.sh: command not found`. See CLAUDE.md's Conventions section for repair commands.
- **`chezmoi/dot_config/zellij/`** — `config.kdl`, `layouts/{dev,ops}.kdl`, `themes/catppuccin-mocha-mauve.kdl`. All static (not templates), LF, UTF-8, mode `100644`; Windows-ignored via the existing target path `.config/zellij` in `.chezmoiignore.tmpl`, so a new subdir needs **no** ignore entry. **KDL comments are `//`, never `#`** — one `#` line invalidates the whole file and zellij falls back to built-in defaults *silently*. **Theme-name dual-edit:** `theme "catppuccin-mocha-mauve"` in `config.kdl` ↔ the block name in `themes/catppuccin-mocha-mauve.kdl`; a dangling name is silent (`zellij setup --check` still says *Well defined*), so `check_zellij_config` in `scripts/check-invariants.sh` asserts the pair. The theme is **derived from the built-in `catppuccin-mocha` compiled into the zellij binary** (`strings -n 6 /usr/local/bin/zellij | grep -A 120 'catppuccin-mocha.kdl'`), re-accented green→mauve; every deviation carries a `CHANGED` comment — re-derive on a `ZELLIJ_VERSION` bump in case upstream restyles underneath. `frame_unselected` is a Styling field the KDL parser does **not** read — don't add it. Load-bearing values not to "clean up": `copy_command` stays **unset** (OSC 52 is the only clipboard path that crosses SSH — see `verification.md`); `web_server false` + `web_sharing "disabled"` are **not** redundant with upstream defaults, because `tools.mk` installs the web-*capable* build (`--asset '^no-web'` is eget's anti-match, excluding the no-web tarball); `serialize_pane_viewport` writes real pane output to `~/.cache/zellij` on the host, a deliberate secrets-on-disk tradeoff documented in the config comment. Config is read at **session creation** — `zellij kill-session main` before verifying any change. **`pane_frame_style "full"` is version-coupled and load-bearing:** zellij 0.45 introduced the key and defaults it to `"titles"` (a title line above each pane) where 0.44 always drew a full frame, so without it the 0.45 upgrade silently flattens the UI — measured on 0.45.1 in an identical window, rounded frames go 1 → 0 and mauve paints 90 → 4, because `frame_selected` has no border left to draw. It is safe on both versions: 0.44.3 **ignores** the unknown key at runtime rather than rejecting the file (verified by painting a session — frames drawn, theme applied, no fallback to the built-in green), so config and binary can roll out in either order. Two other 0.45 defaults were left alone deliberately: `stacked_pane_list` (new stacked rendering — upstream's considered improvement, and no tracked layout uses stacks) and `support_kitty_graphics_protocol` (auto-detects the host terminal, which is the correct behaviour). When bumping ZELLIJ_VERSION, re-run the paint test in `docs/claude/verification.md` — upstream changed UI defaults without changing the config schema, so a clean `setup --check` proves nothing here. The `zs [session] [layout]` helper in the `dot_zshrc.tmpl` ↔ `dot_bashrc.tmpl` parity pair must use **`--new-session-with-layout`**, not `--layout`: with `--session`, `--layout` means *add this layout to that session as new tabs* and dies with `Session '<name>' not found` when it doesn't exist yet. (Bare `zellij -l <layout>`, with no `--session`, does start a new session — that form is fine and is what `README.html` documents.) The `zr` floating-run helper and the `_zj_tab_name` cwd→tab-name hook are part of the same parity pair (zsh registers it on `chpwd`; bash has no `chpwd`, so it hooks `PROMPT_COMMAND` and guards on `$PWD` — both carry the `WORKSTATION_ZELLIJ_TAB_NAMES=0` opt-out and a re-source guard). **zjstatus (the tab bar):** `config.kdl`'s `plugins { tab-bar location="file:zjstatus.wasm" {…} }` overrides the bare alias the built-in default layout references — keep the location RELATIVE (zellij resolves it against `/usr/share/zellij/plugins` and then its DATA dir `~/.local/share/zellij/plugins/` — where `tools.mk`'s `USER_TOOL zjstatus` installs the file via `lib/zellij-plugin.sh`, which asks `zellij setup --check` for `[PLUGIN DIR]` — and the string is the `~/.cache/zellij/permissions.kdl` key; `file:~/…` dumps as an absolute path per host — verified 0.45.1). **Not `~/.config/zellij/plugins/`:** zellij never searches it; the first cut installed there and every session showed "ERROR IN PLUGIN" (2026-09-13) while `dump-layout` looked fine — read `/tmp/zellij-<uid>/zellij-log/zellij.log` (`Loaded plugin` vs `No such file`) to judge a load. Nothing plugin-related lives under `dot_config/zellij/` in the repo (4 MB binary, make-installed). The rounded pills are Nerd Font U+E0B6/U+E0B4 between the style tags — client-font rendered like the powerline arrows, INVISIBLE in most editors and dropped once (2026-09-13, square blocks); `check_zellij_config` counts them, so keep them balanced when editing a pill string. Keep the built-in `status-bar` alias untouched (its hints come from this config). `layouts/{dev,ops}.kdl` end with the verbatim `zellij setup --dump-swap-layout default` block (re-dump on a `ZELLIJ_VERSION` bump) and use bare `tab-bar`/`status-bar` so the override applies; status-bar `size=1` matches 0.45's built-in. Bumping zjstatus = `ZJSTATUS_VERSION` + `ZJSTATUS_ZELLIJ_FLOOR` in `versions.mk` from the release notes (`check_zjstatus_zellij_coupling`).
- **Do NOT add `zellij-autolock`** (or assume any 19-month-old zellij plugin still works). Tested against 0.44.3 on 2026-08-31: the plugin loads and its config parses, but it logs `No command detected.` forever and never locks. Root cause is upstream, not the plugin's packaging — zellij 0.44.3 does not expose a shell pane's foreground command at all: with **stock** zellij config and Helix running, `zellij action list-panes` still reports `terminal_0  terminal  Pane #1`. Note it also needs a one-time interactive permission grant per host (`~/.cache/zellij/permissions.kdl`, keyed by absolute plugin path), which is its own fleet-deployment problem. `Ctrl+g` Locked mode is the built-in, working substitute. Re-test only if the plugin ships a release newer than 0.2.2.

- **`Invoke-CurlRequest` (duplicated verbatim in `bootstrap.ps1` AND `scripts/install-nerd-fonts.ps1`) + `scripts/test-curl.ps1`** — the ONLY Windows HTTP transport (curl.exe; no `Invoke-WebRequest`/`Invoke-RestMethod`/`irm | iex` anywhere — temp-file download + checked native exit code means a truncated fetch can never be executed or installed). **The two copies MUST stay byte-identical** (bootstrap runs from memory before the repo exists; the font script is also runnable standalone for a manual retry) — `check-invariants.sh` `check_curl_helper_parity` diffs the function bodies (pre-commit + `make lint` + Linux CI) and `test-curl.ps1` re-asserts it on Windows; edit both in the same commit. Flags are load-bearing: `--fail` (HTTP ≥400 → exit 22), `--location`, `--retry 3 --retry-delay 2` (transient = timeouts + 408/429/5xx), `--connect-timeout 30`, `--speed-limit 1 --speed-time 60` (stall abort → exit 28, which `--retry` treats as transient; WITHOUT it a connected-but-stalled mirror hangs the bootstrap forever and `--retry` never fires — the old `Invoke-WebRequest` path had a 300 s read timeout), `--disable` (ignore `.curlrc`), `--silent --show-error` (stderr carries only curl's diagnostic, captured via `2>&1` into the thrown message so `Write-Warn` shows the HTTP status, not just "exit 22"). **`Get-Command curl.exe -CommandType Application` returns EVERY curl.exe on PATH** (System32 + Git's `mingw64\bin` — the GitHub windows runner, and any Git-for-Windows install with Unix tools on PATH): always `| Select-Object -First 1`, or `$curl.Source` is an array and `&` fails with "The term 'C:\…\curl.exe C:\…\curl.exe' is not recognized" (CI caught it on #146; `test-curl.ps1` shadows a second curl.exe to keep it covered). Headers go via `--header @<tempfile>` written as UTF-8 **without BOM** (a BOM would corrupt the first header name), never argv — the PAT must not sit in a process command line. `test-curl.ps1` is pure ASCII (glyphs via `[char]0x…`) so it needs no BOM; it MUST end with `$global:LASTEXITCODE = 0` — the GitHub runner appends `exit $LASTEXITCODE` to every `pwsh`/`powershell` step and the script's last native call is a deliberate connection-refused fixture (curl exit 7), so without the reset the `windows-http` job goes red on a passing run. Known behavioural difference vs the replaced `Invoke-WebRequest` path: curl.exe honours `HTTPS_PROXY`-style env vars but NOT the Windows (WinINET/PAC) system proxy.
