# Files Claude should be careful with

> Claude-internal reference, split out of `CLAUDE.md` to keep it lean. CLAUDE.md
> carries a compact risk-category summary; this file holds the full per-file
> detail. **Before editing any file listed here, read its entry first.** Repair
> one-liners (CRLF, executable bit, BOM) live in CLAUDE.md's "Conventions and
> rules of thumb" section.

- **`dotfiles/dircolors`** — Catppuccin Mocha `LS_COLORS` database (GNU `dircolors -p` default recolored to truecolor), eval'd by both shell rc files. `dircolors` only emits `LS_COLORS` when a `TERM` directive matches `$TERM` — the fleet's `TERM=xterm-256color` (Windows Terminal) and the multiplexer TERMs are covered by the stock globs (`xterm*`, `screen*`, `tmux*`); don't prune those directives, and any future custom `TERM` needs its own line or listings silently lose all color. The db also carries `COLORTERM ?*`, but it does NOT rescue an unmatched `TERM` (verified on coreutils 8.32: `TERM=dumb COLORTERM=truecolor` still yields an empty `LS_COLORS`) — it's kept only as a harmless secondary catch-all for newer coreutils, never relied upon. `[dotfiles]` `copy` entry in `config.linux.toml`, both scopes; declared only there, so it never reaches Windows.
- **`dotfiles/config/zsh/plugins/zsh-shift-select.zsh`** — vendored from `jirutka/zsh-shift-select` at a pinned tag (recorded in the file's leading `#` header: tag `v0.1.1`, commit, upstream sha256). MIT, single file, zero deps. Provides the `shift-select` ZLE keymap + Shift+Arrow selection widgets at the prompt. Static, **LF-only**, a `[dotfiles]` `copy` entry (`config.linux.toml`, both scopes — a general shell nicety, no dev gate). Editing this file by hand defeats the vendoring contract — bump by re-downloading the pinned tag, refreshing the sha256, and updating the header. Sourced (and supplemented) by `dotfiles/zshrc.tera`.
- **`dotfiles/config/zsh/completions/_cht.sh`** — vendored zsh completion for the `cht.sh` command, from `https://cheat.sh/:zsh` (rolling source — pinned by snapshot date + body sha256 in the file's header, since upstream publishes no version tag). **`#compdef cht.sh` MUST be the literal first line** (zsh's autoload tag); the vendored header sits on lines 2+, never above it. Static, **LF-only**, part of the `[dotfiles]` `copy` entry for the whole `~/.config/zsh/completions` directory (`config.linux.toml`). Autoloaded because `dotfiles/zshrc.tera` prepends `~/.config/zsh/completions` to `$fpath` *before* `compinit`. Calls `curl cheat.sh/:list` at completion time (needs network). bash has no counterpart — upstream ships no `:bash` completion (parity note in `dotfiles/bashrc.tera`). Bump: re-download, refresh the sha256 + snapshot date, keep `#compdef` first.
- **`dotfiles/config/zsh/completions/_{bootstrap.sh,manage-hosts.sh,update-hosts.sh}` + `dotfiles/config/bash/completions.bash`** — FIRST-PARTY flag completions for the repo scripts (unlike the vendored `_cht.sh` above — edit these normally, no `.vendor` bump dance). The zsh trio autoloads from the same `~/.config/zsh/completions` `[dotfiles]` entry as `_cht.sh` (`#compdef` on the script basename, so `./bootstrap.sh` and `scripts/manage-hosts.sh` invocations both match); the bash file is its own `copy` entry and is SOURCED from `dotfiles/bashrc.tera` (mode 0644, no shebang — it is not a script; it IS in the shellcheck/shfmt first-party arrays, while the zsh files are zsh syntax and stay out). Their Windows counterpart is the external completer + `workstation_*_flags` records in `dotfiles/windows/AppData/Roaming/nushell/config.nu.tera`. ALL surfaces are locked to their scripts' actual flags by `check-invariants.sh`'s flag-parity check — adding/renaming a flag in `bootstrap.sh`/`manage-hosts.sh`/`update-hosts.sh`/`bootstrap.ps1`/`manage-hosts.ps1` fails the check until every completion surface is updated (or the flag is deliberately excluded in the check, like bootstrap.sh's removed `--full` and its `--checkforupdates` alias). `dotfiles/config/bash/` is declared only in `config.linux.toml`, so it's Linux-only by construction — no separate ignore entry needed.
- **`dotfiles/config/zsh/plugins/zsh-autosuggestions/`** — vendored `zsh-users/zsh-autosuggestions` v0.7.1 (MIT), single combined `zsh-autosuggestions.zsh`. Provenance in the `.vendor` sidecar, excluded from deploy by the `[dotfiles]` `copy` entry's `exclude = [".vendor", ".gitkeep"]` (`config.linux.toml`, both scopes). Static, **LF-only**, 0644 (sourced, not executed). Sourced from `dotfiles/zshrc.tera` after fzf-tab; suggestion color via `ZSH_AUTOSUGGEST_HIGHLIGHT_STYLE` (Catppuccin overlay0 `#6c7086`). Bump = re-download the tag, replace the file, refresh `.vendor`.
- **`dotfiles/config/zsh/plugins/zsh-syntax-highlighting/`** — vendored `zsh-users/zsh-syntax-highlighting` 0.8.0 (BSD-3-Clause): entry `zsh-syntax-highlighting.zsh` + the full `highlighters/` tree (entry uses `${0:A:h}` to locate it — keep intact), plus `.version` **and** `.revision-hash` (real names now, no `dot_` prefix to remember). The entry reads BOTH at load and the `.revision-hash` read has no `2>/dev/null`, so a missing `.revision-hash` prints to stderr on every startup — both must be vendored. `.vendor` sidecar excluded via `exclude = [".vendor", ".gitkeep"]`. Bump = re-download the tag, replace files (incl. both dotfiles), refresh `.vendor`.

Bump = re-run the `git ls-remote --tags` check, re-download, refresh `.vendor`.
- **`dotfiles/config/zsh/plugins/zsh-history-substring-search/`** — vendored `zsh-users/zsh-history-substring-search` v1.1.0 (BSD-3-Clause), single self-contained `zsh-history-substring-search.zsh` (the `.plugin.zsh` loader isn't needed). `.vendor` sidecar excluded. Static, **LF-only**, 0644. **Sourced LAST** in `dotfiles/zshrc.tera` (AFTER zsh-syntax-highlighting, per upstream), then ↑/↓ are bound to `history-substring-search-up`/`-down` (xterm `^[[A` + app-mode `^[OA` + terminfo `kcuu1/kcud1`). atuin's `--disable-up-arrow` keeps ↑/↓ free for it. bash parity: readline `history-search-backward`/`-forward` on ↑/↓ (prefix, vs zsh substring). Bump = re-download the tag, refresh `.vendor`.
- **`dotfiles/config/zsh/plugins/zsh-you-should-use/`** — vendored `MichaelAquilina/zsh-you-should-use` 1.11.1 (**GPL-3.0** — recorded in `.vendor`), single `you-should-use.plugin.zsh`. `.vendor` sidecar excluded. Static, **LF-only**, 0644. Pure preexec hook (no ZLE binding → load order loose); `YSU_MESSAGE_POSITION=after`, soft mode (never sets `YSU_HARDCORE`). zsh-only, no bash analog (PARITY NOTE in `dotfiles/bashrc.tera`). Bump = re-download the tag, refresh `.vendor`.
- **`dotfiles/local/bin/batpipe`** — vendored `eth-p/bat-extras` standalone `batpipe` (release `v2024.08.24`, MIT), a single self-contained bash script (the build bundles its `bat-modules` lib inline — no companion files). **Carries a documented 2-line local patch** (NOT verbatim upstream): the bundled `proc.sh` parent-detection used `awk '{… printf $i" " …}'` — a process-argv field as a printf format string — which gawk-aborts whenever any ancestor process's argv contains a `%` conversion, crashing batpipe so `less <file>` fell back to the raw file (no highlight, raw archive bytes). Patched both probes to `printf "%s ", $i`; the bug is still in upstream master (`lib/proc.sh:14,60`), so re-apply on every bump. Provenance + patch details + both sha256s live in `dotfiles/local/bin/.vendor`, excluded from the `~/.local/bin` `[dotfiles]` `copy` entry's `exclude = [".vendor", ".gitkeep"]` (`config.linux.toml`, both scopes). **LF-only**, git mode 0755 (propagated onto the target by `copy`). Wired as the `less` input preprocessor by `eval "$(batpipe)"` in `dotfiles/zshrc.tera` + `dotfiles/bashrc.tera` (guarded on `bat` + `batpipe`), which sets `LESSOPEN`→batpipe, appends `-R` to `LESS`, and sets `BATPIPE=color` — **required** (bat writing into a pipe to `less` defaults color off; `BATPIPE=color` forces `bat --color=always`). Replaces the base `less` package's `/usr/bin/lesspipe.sh` as `LESSOPEN` (system lesspipe left installed as the guard-fail fallback). No `config.toml [vars]` entry — pinned only in `.vendor`. Bump = re-download the release zip, replace with `bin/batpipe`, **re-apply the local patch**, refresh `.vendor`.
- **`dotfiles/config/gdb/gef.py` + `dotfiles/gdbinit.tera`** — the GEF GDB front-end. `gef.py` is the vendored single-file `hugsy/gef` script (MIT), **verbatim upstream, no local patch**, **tag-pinned to release `2024.06`** (sha256 in `dotfiles/config/gdb/.vendor`, excluded from the `~/.config/gdb` `[dotfiles]` `copy` entry). **The pin is a hard Python-version floor, not a stale oversight:** 2024.06 is the last GEF supporting Python 3.6–3.9; `2025.01`+ needs Python 3.10 (`match` syntax). EL9 gdb embeds Python 3.9, so a newer GEF SyntaxErrors at load and spams a traceback on every `gdb` start — **do NOT bump past 2024.06 while the fleet is EL9** (the `.vendor` sidecar has the constraint + an EL9 verify recipe; `gef-legacy` is Python2-only, not a fallback). Deploys 0644 to `~/.config/gdb/gef.py`. `dotfiles/gdbinit.tera` deploys to `~/.gdbinit` (`template` mode) and `source`s `gef.py` by **absolute path** via `{{ env.HOME }}` — it's a `.tera` template ONLY to resolve that absolute path (gdb's `source` doesn't shell-expand `~`); don't add other logic to it. **Both dev-only + Linux-only** via `config.host.toml`'s `host` token — Windows never loads that config file at all, and prod hosts never carry the `host` token, so no separate ignore-list is needed (unlike chezmoi's old target-path `.chezmoiignore` entries). GEF auto-loads into *plain* `gdb`; the other front-end, pwndbg, is a separate command — a mise tool (`github:pwndbg/pwndbg` in `config.dev.toml`) — so they never collide. No `config.toml [vars]` entry. Bump = re-download `gef.py` at the new commit + refresh the `.vendor` sidecar; `dotfiles/gdbinit.tera` needs no change.
- **`dotfiles/local/bin/winterop`** — first-party (NOT vendored) Windows-interop helper for Linux-on-Windows shells (`winterop`). Single self-contained bash script: detects WSL2 / WSL1 / a Hyper-V·VMware·VirtualBox·KVM VM (via `systemd-detect-virt` + the `is_wsl()` probe shared with `bootstrap.sh`), then drives the Windows side through `powershell.exe`/`wslpath`/`clip.exe`/binfmt interop with subcommands `run`/`exe`/`path`/`clip`/`open`/`notify`/`ps`/`reg`/`env`/`host`/`selftest`. In a plain VM the live subcommands refuse with an SSH / shared-folder / RDP pointer (the default report shows the same guidance). **LF-only**, git mode 0755, part of the `~/.local/bin` `[dotfiles]` `copy` entry (`config.linux.toml`, both scopes). **First-party → it IS shellchecked** by `check-invariants.sh` (added explicitly to the shellcheck `targets`); it also rides the LF/mode `dotfiles/local/bin/*` glob — distinct from vendored `batpipe`, which is LF/mode-checked but shellcheck-excluded. `open` uses PowerShell `Start-Process` (not `explorer.exe`) so it survives `appendWindowsPath=false` (which trims `C:\Windows` off PATH). No `config.toml [vars]` entry. Smoke-test: `winterop selftest`.
- **`dotfiles/zshrc.tera` Shift+Arrow block** — sources the vendored `zsh-shift-select.zsh`, then layers two supplements the upstream plugin lacks: (1) **replace-on-type** — overrides `shift-select::deselect-and-input` so a single printable key excises the active region via a direct `$BUFFER[1,from]…$BUFFER[to+1,-1]` slice (no kill-ring pollution) before the key self-inserts; (2) **OSC 52 copy** — wraps the `copy-region-as-kill` widget (`Alt+W`) to also emit `\e]52;c;<base64>\a` so the selection reaches the system clipboard over SSH. `zmodload zsh/parameter zsh/zleparameter` pre-loads the modules backing `$functions`/`$widgets` (it runs unconditionally, before the block — it is NOT itself a guard); each supplement is then individually guarded by an existence check — `${+functions[shift-select::deselect-and-input]}` for replace-on-type, `${+widgets[copy-region-as-kill]}` **plus** `command -v base64` for the OSC 52 path — and the whole block is gated on `[[ -r … ]]`, so it's a no-op if the vendored file isn't applied yet. `Ctrl+C` is deliberately NOT rebound (stays SIGINT). The override relies on the widget→function name mapping (redefining the function re-points the existing widget) — do not rename `shift-select::deselect-and-input` without re-checking against the vendored file. **Parity pair:** `dotfiles/bashrc.tera` carries the bash side (movement-only `bind` lines — readline can't render a live selection); the asymmetry is intentional and commented in both files. Any change to the bound key set must land in both.
- **`dotfiles/config/tealdeer/config.toml`** — tracked tealdeer (tldr) config. `[updates] auto_update = true` is the freshness mechanism: tealdeer auto-downloads the page cache on the first `tldr <cmd>` when the cache is missing or older than `auto_update_interval_hours` (720h). Static, `[dotfiles]` `copy` entry (`config.linux.toml`, both scopes — tldr is a scope-tool, no dev gate). Removing `auto_update` re-breaks `tldr` on fresh hosts (empty-cache → "Page cache not found"). Paired with `tasks/bootstrap`'s tldr-cache-seed step below.
- **`tasks/bootstrap` (tldr cache seed step)** — seeds the tealdeer cache once so `tldr` works instantly post-provision instead of erroring until the first `auto_update`. Runs on every host (no OS gate needed inside a bash task the way `.chezmoiscripts/` needed its own `{{ if eq .chezmoi.os "linux" }}` guard — this step is just Linux-only by virtue of `tasks/bootstrap` itself being Linux-only). Marker-guarded at `~/.local/state/workstation/tldr-cache` (checked BEFORE any work — `[ -d ~/.cache/tealdeer/tldr-pages ]` also short-circuits it if the cache already exists from `auto_update`). Soft-fails (prints a warning, no `set -e` abort) if `tldr` isn't on PATH yet or `tldr --update` fails (offline) — `auto_update` in `dotfiles/config/tealdeer/config.toml` is the backstop in every skip path, so the seed being best-effort is safe.
- **`hosts.conf`** — prefer the manage-hosts scripts; manual edits lose dynamic padding/sort until next save. Column 4 (group) must be `dev_machine` or `prod_machine`.
- **`bootstrap.sh`** — thin seed only. No per-tool versions, no install logic. It computes `MISE_ENV` itself via `scripts/lib/mise-env.sh <dev|prod>` (no `scope.mk` to defer to any more — that file is gone), then writes/migrates `config.local.toml` (`ensure_config_local()`), runs `scripts/lib/mise-install.sh` (tools) followed by `mise bootstrap --yes` (everything in `[bootstrap.*]` + `[dotfiles]`, `--force-dotfiles` on the first run only).
- **`GNUmakefile` + `makefile/` are GONE (PR2).** There is no Makefile anywhere in this repo any more — `bootstrap.sh` runs `mise bootstrap` directly. If you find yourself reaching for a `make` target from muscle memory, the mapping is: `make MODE=<dev|prod> provision` → `mise bootstrap --yes`; `make tools` → the tools phase of the same (or `mise bootstrap --only tools --yes`); `make doctor` → `mise run health`; `make check-updates` → `mise run check-updates`; `make lint`/`install-hooks`/`fmt`/`ps-lint`/`secrets` → `mise run lint`/`install-hooks`/`fmt`/`ps-lint`/`secrets`; `make wsl-config` → `mise bootstrap --only files,services --yes` (or narrower with `--only`); `make dozzle-service`/`cockpit-service`/`rsyslog-service` have no mise equivalent any more — that provisioning was removed entirely 2026-09-22 (see `CLAUDE_CHANGELOG.md`); `make python-env`/`nerd-fonts`/`vcpkg` → `mise run python-env`/`fonts`/`vcpkg`; `make list` → `mise tasks ls` (tasks) + `mise ls` (tools) + `mise bootstrap status` (host state).
- **`config.host.toml` / `config.native.toml` / `config.wsl.toml`** — the successors to `scope.mk`/`packages.mk`/`shell.mk`/`dotfiles.mk`/`versions.mk`'s host-state half. `config.host.toml` is dnf packages (dev-only) plus the `pre-packages` EPEL/CRB hook, PLUS the Linux-dev-only dotfiles (`~/.gdbinit`, `~/.config/gdb`, `~/.config/herdr/config.toml`); `config.native.toml` is the NFS client dnf package group only (non-WSL dev; docker/cockpit/rsyslog/Dozzle provisioning was removed entirely 2026-09-22, see `CLAUDE_CHANGELOG.md`); `config.wsl.toml` is `/etc/wsl.conf` (WSL dev only). None declares `[tools]` — lock coverage stays exactly `mise.lock`/`mise.linux.lock`/`mise.dev.lock`. `MISE_ENV` tokens (`host`/`native`/`wsl`, from `scripts/lib/mise-env.sh`) pick which of the three load — prod hosts (`MISE_ENV=linux`) load none of them, by construction: **never** add a table (`[bootstrap.*]` OR `[dotfiles]`) that needs root or is dev-only to `config.toml`/`config.linux.toml`/`config.dev.toml`. `[bootstrap.*]`/`[dotfiles]` tables merge by union across every loaded file (verified) — a dnf package / `/etc` file / service / dotfile can be declared in whichever file its `MISE_ENV` token gates; don't duplicate a declaration across files.
- **`config.toml` / `config.linux.toml` / `config.dev.toml` / `config.windows.toml`** — the mise tool declarations AND the `[dotfiles]` tables, PLUS `config.toml`'s `[vars]` table (the host pins Make used to own — `python_version`, `nerd_font_version`, `vcpkg_version`, `zjstatus_zellij_floor`). This repo root IS mise's global config dir (Linux `~/.config/mise`, Windows `%USERPROFILE%\.config\mise` — no symlink, no copy). `config.toml` is cross-platform (`uv`, `python` tools; `gitconfig.tera`/`ssh/config.tera`/`starship.toml` dotfiles — both scopes, both OSes); `config.linux.toml` is the Linux toolbelt (both scopes; also carries `[bootstrap.services.pueued]`, the `post-tools`/`post-dotfiles` hooks, and the bulk of the Linux `[dotfiles]` entries — see below); `config.dev.toml` is dev tools + dev-only dotfiles on both OSes, with `os = ["linux"]` on tool entries that are dev-only AND Linux-only; `config.windows.toml` is the 13 Windows-only dotfiles (loads with the `windows` token, alongside `config.toml`+`config.dev.toml`). Prefer the aqua-registry short name (`fzf = "0.74.3"`); fall back to `github:`/`http:` only when the registry picks the wrong asset (comment why — an EL9 glibc floor, a bare/ambiguous asset, no GitHub release) or `mise lock` needs a dependency-locked `pypi:`/`npm:` install. **Never hand-edit for a version bump without also refreshing the lockfiles** (see below) — `mise config set` is the safer edit path, though bumping a STRING entry (`tool = "1.2.3"`) drops BOTH its trailing comment AND the comment line above it, while bumping a TABLE entry's `.version` preserves both (see `docs/claude/verification.md`). `sync-tool-memory.sh` regenerates the machine-level Claude memory TOOLS block on every edit to `config.toml`/`config.*.toml`. **Editing a `[dotfiles]` entry:** the key is the TARGET path (`"~/.foo"`), `source` is relative to the repo root, `mode` is `copy` or `template` in this repo (mise's schema also has `symlink`/`symlink-each`/`track`, but ruling 7 — 2026-09-22 copy-migration — retires both symlink modes here entirely; `check_dotfiles_config` fails the build if either reappears) — verify with `mise dot apply --force --yes -- "<target>"` and `bash scripts/check-invariants.sh` (`check_dotfiles_config`).
- **`mise.lock` / `mise.linux.lock` / `mise.dev.lock` + `locks/**`** — mise-generated lockfiles (one per config file) plus per-tool sidecars under `locks/<lockfile-stem>/<backend>-<tool>/<version>` for dependency-locked `pypi:`/`npm:` tools (e.g. `locks/mise.dev/npm-ccstatusline`). **Never hand-edit any of these** — regenerate with `mise lock --global --platform linux-x64` (Linux) and `mise lock --global --platform windows-x64` (Windows half; only needed for tools without `os = ["linux"]`) after any `config*.toml` pin change, run from OUTSIDE the checkout with `XDG_CONFIG_HOME` pointing at a throwaway dir whose `mise/` is a symlink to it (unset `MISE_CONFIG_DIR`; see `scripts/bump-versions.sh`'s `mise_global()`/`normalize_lock_sidecars()` helpers) — this is the only invocation form verified, on-host, to merge all three `MISE_ENV`-suffixed config files under `--global`. **mise 2026.9.9 quirk:** `mise lock` itself always (re)writes the pypi:/npm: sidecar refs under a stale `.mise/locks/**` layout, in every invocation form tried — never the tracked `locks/**` layout — so every `mise lock --global` regen must be followed by folding any `.mise/locks/**` content into `locks/**` and repointing the `path = ` refs (`normalize_lock_sidecars()` does this mechanically; don't try to coax `mise install` into doing it instead — mise writes `locks/**` only when its config root is literally `$HOME/.config/mise` — the on-host layout; `MISE_CONFIG_DIR`, the XDG-symlink form, and any other directory get `.mise/locks/**` — which is why `lint.yml`'s install step runs with `MISE_LOCKFILE=false` (`MISE_CONFIG_DIR=$GITHUB_WORKSPACE` would otherwise rewrite `mise.linux.lock` before `check-invariants.sh` runs)). This same global-config-discovery fallback (a scratch `HOME=` with no `.config/mise` of its own silently reads the REAL account home's config instead of erroring) is what `scripts/check-templates.sh` has to work around for `mise dot`/`mise bootstrap` — see that script's own header. `check-invariants.sh`'s `check_mise_config_files` asserts lockfile coverage for every declared tool, that every non-`"latest"` config pin equals its lock entry's `version`, AND that every sidecar `path = ` ref starts with `locks/` and the directory exists. `mise.dev.lock` also carries `platforms.windows-x64` tables for every `os = ["linux"]`-only tool (`mise lock --platform windows-x64` locks the requested platform regardless of the config's `os` restriction) — inert while `os` holds, since mise never installs them on Windows. For the bespoke `github:`/`http:` backends with no Windows-specific `asset_pattern` (DevToys, pwndbg) that table even reuses the identical Linux download URL; aqua-registry/GitHub-backend tools with real per-OS assets (herdr, oh-my-pi, opencode) get a genuine — just unused — Windows binary URL instead.
- **`scripts/lib/mise-env.sh`** — LF-only, mode 100755. `mise-env.sh <dev|prod>` prints the `MISE_ENV` token set for the calling Linux host: `linux` for prod, `linux,dev,host,wsl` or `linux,dev,host,native` for dev (WSL-detected via the same `is_wsl()`-shaped check `bootstrap.sh` uses). Seeded verbatim from this host's actual `.wslconfig` (its real `[experimental]` block: `networkingMode=mirrored`, `dnsTunneling`, etc.) under a short doc header — same "track current values verbatim" approach as `configs/wsl/wsl.conf`, so applying it PRESERVES the host's WSL2 tuning instead of blanking it. (A pre-existing `%USERPROFILE%\.wslconfig` was discovered at first apply; a blank template would have wiped it.) Editing it triggers a `bootstrap.ps1` step that sha256-compares the source against a stored marker (mise has no `run_onchange` equivalent, ruling 6) and prints the `wsl --shutdown` restart reminder on a change. **`sparseVhd=true` and `autoMemoryReclaim=gradual` are deliberate, annotated in-file** — sparse is inert on WSL >= 2.5 (upstream-disabled over corruption reports, microsoft/WSL#13075; self-activates if re-enabled), reclaim pins slow-trim over the `dropCache` default; do NOT "clean them up" or move them to `[wsl2]` (they're `[experimental]`-section keys).
