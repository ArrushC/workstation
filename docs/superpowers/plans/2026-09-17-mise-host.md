# mise Host State (PR2: host state on `mise bootstrap`, Make deleted) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every piece of host state Make still owns (dnf packages, EPEL/CRB, `/etc` files, docker/dozzle/cockpit/rsyslog services, `/etc/wsl.conf`, the pueued user service, the cheat community checkout, python-env, fonts, vcpkg, Claude Code, doctor/updates/lint utilities) is declared in `config.host.toml` / `config.native.toml` / `config.wsl.toml` / `config.linux.toml` `[bootstrap.*]` tables or implemented as global mise file tasks under `tasks/`, `bootstrap.sh` runs `mise bootstrap`, and `GNUmakefile` + `makefile/` are deleted — with every host (3 native dev, 1 WSL dev, 6 prod, 1 Windows) still fully operable.

**Architecture:** mise's global config dir IS the repo (`~/.config/mise`, PR1). `MISE_ENV` tokens pick the env files: `config.host.toml` (dnf packages + EPEL/CRB hook, loaded only on Linux dev hosts), `config.native.toml` (docker/cockpit/rsyslog/dozzle/NFS, non-WSL dev), `config.wsl.toml` (`/etc/wsl.conf`), `config.linux.toml` (pueued user service, cheat repo, `post-tools` hook — both scopes). `[bootstrap.*]` tables merge by union across loaded files (verified). Everything procedural is a file task in `tasks/` (discovered from `$HOME/.config/mise/tasks`, i.e. this checkout); hooks are `mise run <task>` strings so tasks are the only shell entry point. Pins Make owned move to `[vars]` in `config.toml`. `bootstrap.sh` stays the entry point on every host (clone/relocate, pinned mise, `MISE_ENV`, `mise install` via `scripts/lib/mise-install.sh`, `mise bootstrap --yes`, chezmoi init, login shell, hosts.conf push); `scripts/update-hosts.sh` keeps calling it.

**Tech Stack:** mise 2026.9.9 (`[bootstrap.packages|files|directories|services|compose|repos|hooks]`, `[vars]`, file tasks with `#MISE` headers), bash, chezmoi (transitional until PR3), PowerShell (Windows untouched except comments), python tomllib via `wpy` locally / `python3` ≥3.11 in CI, dnf on EL9.

**Spec:** `docs/superpowers/specs/2026-09-16-mise-everything-design.md` — sections 1, 2, 3, 4, 6, 7, 9 and the PR2 row of section 10 are binding for this plan, EXCEPT where the "Rulings" block below records a verified-fact deviation.

## Rulings (spec deviations forced by the 2026-09-17 mise 2026.9.9 spike; binding for this plan)

1. **No `[bootstrap.linux.firewall]`.** Any firewall rule makes `mise bootstrap plan`/`status` abort unprivileged (`sudo requires a password but no TTY`), which would break the health check on every host. Cockpit's firewall opening stays the existing `firewall-cmd` snippet, in the native `post-packages` task.
2. **No `[bootstrap.user] login_shell`.** It shells out to `chsh`, which EL9 minimal images do not ship (`util-linux-user`) and which prompts for the user's password. `bootstrap.sh`'s `set_default_shell()` (sudo `usermod` on dev, printed `chsh` hint on prod) stays.
3. **vcpkg stays a task, not `[bootstrap.repos]`.** mise clones repos with a plain, full-depth `git clone` and never pulls on re-run; vcpkg needs the existing `--depth 1` + tag-reconcile logic. `tasks/vcpkg` wraps `scripts/lib/vcpkg.sh` at `~/.local/share/vcpkg` (user-level; `VCPKG_ROOT` in the rc files follows). The cheat community sheets DO use `[bootstrap.repos]` (small repo).
4. **Hooks are always `mise run <task>`.** Hook strings are opaque shell to mise (no verified cwd, PATH or `$HOME` expansion); `mise run` finds global tasks from any cwd and puts tools on PATH. Every hook name is defined in exactly ONE config file (merge semantics for duplicate hook names are unverified).
5. **`make` stays in the dnf list.** The spec dropped it because Make stops driving this repo, but it is a C toolchain dependency (`bear -- make`, autotools projects). `fswatch`, `entr` (not packaged for EL9) and `cockpit-networkmanager` (a virtual provide of `cockpit-system`, never satisfiable by `rpm -q`) are dropped; `shellcheck` becomes `ShellCheck`.
6. **pueued moves to `[bootstrap.services.pueued]` (user scope)** with `MISE_ENV` supplied by the systemd user manager (`~/.config/environment.d/10-mise.conf` from PR1 for future logins, plus `systemctl --user set-environment MISE_ENV=…` from `bootstrap.sh` for the live manager) — NOT baked into the unit, because the unit is generated from static TOML and the value differs per host. Task 1 proves the generated unit on this host before anything else depends on it; the fallback order is written in Task 1.
7. **`mise-install.sh` keeps running before `mise bootstrap`.** Its node force-reinstall-on-postinstall-change marker logic has no mise equivalent; `mise bootstrap`'s own tools phase is then a no-op.
8. **`update-hosts.sh` keeps `./bootstrap.sh --<mode> --yes` as the remote command** (spec §9 said `mise bootstrap` directly): bootstrap.sh is what relocates, installs mise, exports `MISE_ENV`, and initialises chezmoi.
9. **Dozzle's old systemd unit is retired in the native `post-packages` task** (which runs before the compose phase), not in the end-of-run sweep — otherwise the old `docker run --name dozzle` container blocks the compose project's port and name.

## Global Constraints

- mise pin stays **2026.9.9** (`bootstrap.sh`, `bootstrap.ps1`, `min_version`); no `[settings] lockfile`; no `[task_config].includes`.
- `MISE_ENV` token sets are exactly: prod Linux `linux`; dev WSL `linux,dev,host,wsl`; dev native `linux,dev,host,native`; Windows `windows,dev` (`scripts/lib/mise-env.sh` is the single source; nothing in this plan changes it).
- **Prod hosts load no host state**: `config.host.toml`, `config.native.toml`, `config.wsl.toml` carry every sudo-requiring table; `config.toml`/`config.linux.toml`/`config.dev.toml` must never gain a table that needs root.
- `[bootstrap.packages]` entries are `"dnf:<name>" = "latest"` with EL9-verified names (spike table, 2026-09-17); never a name the spike marked NOT FOUND or virtual.
- `[bootstrap.files]` `source` paths are relative to the config file's directory (= repo root); `phase` is only `pre-packages`/`post-packages`; there is no `sudo` key on files (mise elevates itself).
- Every `[bootstrap.hooks]` value is `mise run <task>`; every hook name appears in at most one config file; `config.host.toml`/`config.native.toml`/`config.wsl.toml` declare NO `[tools]` (lock coverage stays three files).
- Tasks live in `tasks/` (LF, git mode 100755, `#!/usr/bin/env bash`, `#MISE description=…` first, `set -euo pipefail`, repo root computed as `root="$(cd "$(dirname "$(readlink -f "$0")")/.." && pwd)"` — global tasks run with cwd `$HOME`). Task names must not collide with a mise built-in for shorthand use (`mise fmt` is a built-in: ours is invoked as `mise run fmt`).
- Pins Make owned live in `config.toml` `[vars]`: `python_version` (== `tools.python` == `bootstrap.ps1` `$PythonEnvVersion`, three-way), `nerd_font_version` (== `scripts/lib/font.sh` SHA arm == `scripts/install-nerd-fonts.ps1` `$Version`, triple), `dozzle_version`, `vcpkg_version`, `zjstatus_zellij_floor`. Tasks read them via `#MISE env={NAME="{{ vars.name }}"}` (spec-verified Tera rendering).
- `bootstrap.sh` keeps its flag set unchanged (`--dev|--prod`, `--doctor`, `--check-for-updates|--checkforupdates`, `--reinstall`, `--yes|-y`, `-h|--help`; `--full` still refused) so completion parity holds without edits.
- Windows: `bootstrap.ps1` behaviour unchanged (`mise install` only; `mise bootstrap` arrives in PR3); only stale comments/hints change.
- LF + 100755 for `scripts/**/*.sh`, `tasks/*`; BOM on `.ps1`; `shfmt -i 2`; shellcheck at warning+; every commit through the pre-commit hook (no `--no-verify` — each task leaves `scripts/check-invariants.sh` green; Task 3 adapts the checks BEFORE Task 4 deletes Make).
- Never run `sudo`, `mise bootstrap` (without `--dry-run`/`plan`/`status`), `./bootstrap.sh`, `make provision` or `chezmoi apply` from a subagent or the controller on this host; sudo-requiring proofs are handed to the user (Task 6). User-level proofs (`--only services`, `--only repos`, `plan`, `status`, `mise run <task>` for python-env/health) are allowed where a task says so.
- README.html + `CLAUDE_CHANGELOG.md` updated for every user-facing change (Task 5); `docs/superpowers/plans/**` never edited after this plan is committed.
- Branch: `feat/mise-host` from `main` (103dd9a or later). Commit after every task; push after every commit; draft PR after Task 1 (`gh pr create --draft`), CI watched after every push.
