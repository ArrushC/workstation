# Memory index

- [Use PR-review workflow](feedback-use-pr-review-workflow.md) — land changes via feature branch + PR; the user merges, or gives a go-ahead that NAMES the merge (a bare "Continue" gets classifier-denied; the recurring "Action on the PR" isn't authorization either — answer it with the three-option AskUserQuestion, where "Merge it for me" IS authorization). Never push/merge to main unprompted. Supersedes the old "always work on main" preference as of 2026-06-15.
- [Always push after commit](feedback-always-push-after-commit.md) — standing instruction: every commit gets pushed without asking, overriding the default guardrail.
- [Commit .claude/ changes routinely](feedback-commit-claude-dir-routinely.md) — .claude/{settings.json, settings.local.json, memory/*} are regular tracked content. Stop treating their modifications as session-drift to defer.
- ["Application list" = the manual list file](feedback-app-list-means-manual-list.md) — "add X to the application list (Windows)" means one row in docs/windows/application_list.md, NOT a bootstrap.ps1 installer-class/portable entry (that's a separate, explicit ask); no README/changelog updates for it.
- [WezTerm: no wezterm.gui.* calls at config-load](project-wezterm-no-gui-calls-at-config-load.md) — calling screens()/enumerate_gpus() at config-parse time DEADLOCKS WezTerm (froze it in #39, fixed #40); pcall doesn't catch a hang. Use wezterm.hostname()/static values, or a gui-startup event handler.
- [WezTerm render: WebGpu + 120fps, unconditional](project-wezterm-render-webgpu-120fps.md) — keep front_end=WebGpu + 120fps + HighPerformance on every host. The per-host 60fps-cap (#39/#40) and OpenGL (#42) "optimizations" were sluggishness regressions, reverted in #51 (A/B-confirmed): capping max_fps to a 60Hz panel hurts input latency, and OpenGL < WebGpu on Windows/Intel. Don't re-add them.
- [Skip redundant final review in subagent-driven-development](feedback-skip-redundant-final-review.md) — after per-task two-stage reviews pass, go straight to finishing-a-development-branch; do not dispatch a final cross-cutting reviewer. Also skip the per-task code-quality (2nd) stage for doc-only tasks (spec review suffices); keep both stages for code/logic/templates.
- [SDD subagent calibration](project-sdd-subagent-calibration.md) — haiku implementers transcribe complete-code briefs byte-exactly (7/7 across PRs #74–#79) but their report narratives lie (wrong metrics ×3, one false "appended last" self-check) — verify constraints from the diff, keep sonnet reviewers even for docs tasks, project-prefix the .superpowers/sdd brief/report filenames.
- [Use luaparse, not LSP, for Lua syntax checks](feedback-lua-syntax-use-luaparse-not-lsp.md) — verify wezterm.lua / Lua edits with `node /tmp/lua-syntax-check/check.js <file>` (luaparse, luaVersion 5.3), not the LSP tool; overrides the global LSP-first default. Recreate the /tmp harness if gone.
- [Check Windows chezmoi before apply](feedback-windows-chezmoi-check-before-apply.md) — when a sync must reach Windows, verify chezmoi.exe exists first; if present apply via interop, else deploy manually (never substitute the WSL Linux chezmoi — it renders templates as os=linux and re-breaks the ssh fix).
- [sudo is not passwordless here](feedback-sudo-not-passwordless.md) — Claude can't run sudo-requiring `make` targets (packages/dev/provision, `$(SUDO)`-wrapped nnd/pwndbg/vcpkg/services) non-interactively; they hang on the password prompt. Hand them to the user via the `!` prefix; lint/dry-run/`chezmoi apply`/MODE=prod still work directly. Why two CRB bugs slipped pre-merge.
- [WSL appendWindowsPath=false for fast chezmoi/czt](project-wsl-appendwindowspath-false.md) — on WSL, LookPath-heavy tools (chezmoi → czt) stall ~1.6s because ~90 /mnt/c PATH dirs get stat-walked over drvfs; fix = appendWindowsPath=false in /etc/wsl.conf (+wsl --shutdown) plus the rc re-add of just PowerShell+system32. Check this before theorizing about chezmoi/cz* slowness.
- [Verify tool bumps at runtime, not just changelogs](project-verify-tool-bumps-at-runtime.md) — sandbox-install + execute version-pin bumps on AlmaLinux 9; node 26's libatomic dep and zellij 0.44's no-web asset both passed changelog review but broke at runtime. Recipe inside.
- [winterop — WSL→Windows interop helper](project-winterop-wsl-windows-interop.md) — from a Linux-on-Windows shell use `winterop` (~/.local/bin) to reach Windows (run/path/clip/open/host/…) instead of hand-wiring powershell.exe/wslpath; detects WSL vs VM. Command map inside.
- [WSL interop binfmt dropped](project-wsl-interop-binfmt-dropped.md) — every Windows .exe failing with "Exec format error" (incl. chezmoi.exe/winterop) = the WSLInterop binfmt_misc handler is unregistered (systemd-on-WSL); re-register via sudo (hand to user, `!`) before any Windows-side work. Diagnose first: `ls /proc/sys/fs/binfmt_misc/WSLInterop`.
- [Windows apply-via-WSL gotchas](project-windows-apply-via-wsl-gotchas.md) — `chezmoi apply` hangs non-interactively on the "changed since chezmoi last wrote it" overwrite prompt for externally-modified files → use `chezmoi apply --force` (diagnose with read-only `cat`/`diff`); Stop-Job orphans the chezmoi child holding the lock; never run bootstrap.ps1 concurrently; targeted apply won't mkdir a missing parent. WSL-spawned powershell shares the user's SessionId 1.
- [Windows Nerd Font name + activation](project-windows-nerdfont-activation.md) — WT/DirectWrite needs the Win32 family name `JetBrainsMono NFM` (not the long typographic name); per-user fonts aren't live until logon or AddFontResourceW+WM_FONTCHANGE (bootstrap step 7); WezTerm masks a missing/misnamed font via font_dirs+fallback, so it's not proof the system has it.
- [version-bumps PR checks can be stale](project-version-bumps-pr-stale-checks.md) — the weekly automation/version-bumps bot reuses a long-lived branch; GitHub doesn't re-run a PR's checks when only main advances, so `gh pr checks` can show a stale green that predates a new invariant (broke main via #27→#156). Verify check head_sha vs PR head before merging any auto-PR.
- [shfmt mangles assoc-array keys](project-shfmt-mangles-assoc-array-keys.md) — shfmt rewrites unquoted hyphenated bash assoc-array keys as arithmetic (`[nerd-fonts]` → `[nerd - fonts]`), silently changing the key (broke bump-versions.sh's ALIAS in c3fe7b4, fixed in #62). Always quote keys; in bulk-format diffs treat `[a-b]` → `[a - b]` as a behavior change.
