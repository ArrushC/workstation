- [WSL appendWindowsPath=false for fast chezmoi/czt](project_wsl_appendwindowspath_false.md) — on WSL, LookPath-heavy tools (chezmoi → czt) stall ~1.6s because ~90 /mnt/c PATH dirs get stat-walked over drvfs; fix = appendWindowsPath=false in /etc/wsl.conf (+wsl --shutdown) plus the rc re-add of just PowerShell+system32. Check this before theorizing about chezmoi/cz* slowness.
- [Verify tool bumps at runtime, not just changelogs](project_verify_tool_bumps_at_runtime.md) — sandbox-install + execute version-pin bumps on AlmaLinux 9; node 26's libatomic dep and zellij 0.44's no-web asset both passed changelog review but broke at runtime. Recipe inside.
- [winterop — WSL→Windows interop helper](project_winterop_wsl_windows_interop.md) — from a Linux-on-Windows shell use `winterop` (~/.local/bin) to reach Windows (run/path/clip/open/host/…) instead of hand-wiring powershell.exe/wslpath; detects WSL vs VM. Command map inside.
- [Windows apply-via-WSL gotchas](project_windows_apply_via_wsl_gotchas.md) — `chezmoi apply` hangs non-interactively on the "changed since chezmoi last wrote it" overwrite prompt for externally-modified files → use `chezmoi apply --force` (diagnose with read-only `cat`/`diff`); Stop-Job orphans the chezmoi child holding the lock; never run bootstrap.ps1 concurrently; targeted apply won't mkdir a missing parent. WSL-spawned powershell shares the user's SessionId 1.
- [Windows Nerd Font name + activation](project_windows_nerdfont_activation.md) — WT/DirectWrite needs the Win32 family name `JetBrainsMono NFM` (not the long typographic name); per-user fonts aren't live until logon or AddFontResourceW+WM_FONTCHANGE (bootstrap step 7); WezTerm masks a missing/misnamed font via font_dirs+fallback, so it's not proof the system has it.
