On 2026-09-24 the user removed the hosts list entirely: `hosts.conf`, `scripts/manage-hosts.{sh,ps1}`, `scripts/update-hosts.sh`, `tasks/update-hosts`, their zsh/bash/Nushell completions, `bootstrap.sh`'s self-registration + hosts.conf commit/push, `bootstrap.ps1`'s Windows Terminal SSH-profile fragment and per-host Warp tabs, and the `hosts` shell command. There is no fleet rollout any more: each host updates itself with `wsu` (or `./bootstrap.sh --<mode>`). `--dev`/`--prod` and `vars.group` (dev_machine/prod_machine) stay — they pick `MISE_ENV`, not an inventory group.

**Why:** "There's not much point in keeping a list and it's primarily the reason why the github repo is private." The user wants the repo to be publishable. History was rewritten with `git filter-repo` the same day: `hosts.conf`, the pre-mise `ansible/inventory/hosts.ini` and the old WezTerm `hosts.lua` were dropped from every commit, and the 11 real host IPs were replaced with `***REMOVED-IP***` in all other files and in commit messages. GitHub's read-only PR refs (`refs/pull/*`) still reached pre-rewrite commits (1,205 commits, the IPs 2,465 times), so the user chose a fresh repo: the old one was renamed `ArrushC/workstation-archive`, archived, and then DELETED the same day (user: no two repos; its 167 PRs were exported first to the untracked `~/workstation-archive-prs.json`, which also removed the last copy of the IP-bearing history via its PR refs), and a new PUBLIC `ArrushC/workstation` was created from the clean `main` alone (no PR refs; anonymous-clone scan found 0 IPs; gitleaks clean). Reusing the name kept every `raw.githubusercontent.com/ArrushC/workstation/...` URL and both checkouts' remotes working unchanged. The new repo needed `actions/permissions/workflow` set to write + can_approve (the user ran it) for the weekly bump PR. Since the repo is public, `GITHUB_TOKEN` is optional everywhere (docs updated): it only lifts the GitHub API rate limit, or authenticates a private fork. Later that day the 225 commits authored as the work email (arrush.chaturvedi@atcoretec.com, 2026-05-25..06-09) were remapped with `git filter-repo --mailmap` to `Arrush Chaturvedi <contact@arrushc.com>` because GitHub credited them to the AtcoreUITeam account; the user chose to KEEP the `claude` contributor (Co-authored-by trailers). PR numbers before #1 in commit messages/docs refer to the deleted repo — look them up in the export file, not on GitHub.

**How to apply:**
- Never add a tracked host inventory, IP address, or per-host launcher back to this repo. Per-host SSH details belong in the untracked `~/.ssh/config.local`.
- The user chose to LEAVE other work-identifying strings as they are (gitconfig's repo.atcoretec.com credential block, Zed remote-SSH projects, a VS Code Atcom regex, hostnames in historical docs/changelog) — don't scrub them unprompted, but flag them if the user asks what still blocks going public.
- Before any history rewrite, rehearse on a fresh `git clone --single-branch` in the scratchpad (`uvx git-filter-repo`), verify with `git rev-list --all | xargs git grep` and `git log --all --format=%B`, and remember commit messages need `--replace-message` too — 7 of them carried IPs.
