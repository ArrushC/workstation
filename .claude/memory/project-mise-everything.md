PR2 of the Make→mise migration (spec `docs/superpowers/specs/2026-09-16-mise-everything-design.md`, plan `docs/superpowers/plans/2026-09-17-mise-host.md`) is merged. Everything Make still owned after PR1 (dnf packages, EPEL/CRB enablement, `/etc` files, docker/dozzle/cockpit/rsyslog services, `/etc/wsl.conf`, the pueued user service, and the doctor/check-updates/lint/fmt/secrets/install-hooks/python-env/fonts/vcpkg/statusline utilities) is now declared as `[bootstrap.*]` tables in `config*.toml` or implemented as global mise file tasks under `tasks/`. `GNUmakefile` and `makefile/` are **deleted** — there is no Makefile anywhere in this repo any more. `bootstrap.sh` runs `scripts/lib/mise-install.sh` (tools) then `mise bootstrap --yes` (packages/files/services/compose/repos/tools-gate/the `bootstrap` task) in place of `make MODE=<dev|prod> provision`. Only PR3 (retiring chezmoi itself, and bringing `mise bootstrap` to Windows) remains.

**New config files, gated by `MISE_ENV` tokens** (`scripts/lib/mise-env.sh` is still the single source of the token sets — unchanged by this PR): `config.host.toml` (`host` token — dnf packages + the `pre-packages` EPEL/CRB hook, dev-only) · `config.native.toml` (`native` token — docker/cockpit/rsyslog/dozzle/NFS, non-WSL dev only) · `config.wsl.toml` (`wsl` token — `/etc/wsl.conf`). None of the three declares `[tools]` — lock coverage stays exactly `mise.lock`/`mise.linux.lock`/`mise.dev.lock`. **Prod hosts (`MISE_ENV=linux`) load none of them** — that's the whole safety property: nothing that needs root can ever load on a host with no sudo. `[bootstrap.*]` tables merge by union across every loaded config file (verified against mise 2026.9.9).

**The nine Rulings** (verified-fact deviations from the original spec, forced by a 2026-09-17 spike against mise 2026.9.9 — binding for this migration, and likely still binding for PR3):
1. **No `[bootstrap.linux.firewall]` table, anywhere.** Any firewall rule makes mise re-exec itself with sudo for that table — including during a read-only `mise bootstrap plan`/`status` call, which then hangs/fails on a host with no TTY. Cockpit's firewall port stays the existing `firewall-cmd` snippet, folded into the `native-post-packages` post-packages hook task instead.
2. **No `[bootstrap.user] login_shell`.** It shells out to `chsh`, which EL9 minimal images don't ship and which prompts for the user's own password. `bootstrap.sh`'s existing `set_default_shell()` (sudo `usermod` on dev, printed hint on prod) stays the only mechanism.
3. **vcpkg stays a task (`tasks/vcpkg`), not `[bootstrap.repos]`.** mise's repo primitive does a plain, full-depth `git clone` and never pulls/reconciles on re-run; vcpkg needs `--depth 1` + tag-reconcile, which only the existing `scripts/lib/vcpkg.sh` logic provides. Nothing uses `[bootstrap.repos]` now: the cheat-community sheets were an entry until the final review showed the repos phase gates everything downstream of it (tools, the post-tools gate, user services, the `bootstrap` task) on a reachable clone URL — they are a soft-failing clone in `tasks/bootstrap` instead.
4. **Hooks are always `mise run <task>`**, never a literal shell one-liner — hook strings get no verified cwd/PATH/`$HOME` expansion the way `mise run` does. Every hook name lives in exactly one config file (merge semantics for a duplicate name are unverified).
5. **`make` itself stays in the dnf package list** (it's a C-toolchain dependency now — `bear -- make`, autotools — not this repo's orchestrator). Three Make-era package names dropped as EL9-unavailable/virtual: `fswatch`, `entr`, `cockpit-networkmanager`; `shellcheck` recapitalises to `ShellCheck`.
6. **pueued's `MISE_ENV` comes from the systemd user manager, never baked into the generated unit.** `dev.mise.pueued.service` (generated by `config.linux.toml`'s `[bootstrap.services.pueued]`) has NO `Environment=MISE_ENV=...` line — the value differs per host (wsl/native/prod), so hard-coding it would be wrong everywhere but one host. Relies on `~/.config/environment.d/10-mise.conf` (future logins) PLUS `bootstrap.sh`'s `systemctl --user set-environment MISE_ENV=…` (this login, live manager).
7. **`mise-install.sh` keeps running before `mise bootstrap`.** Its node force-reinstall-on-postinstall-change marker logic has no mise-native equivalent; `mise bootstrap`'s own tools phase is then a no-op the second time.
8. **`update-hosts.sh` keeps `./bootstrap.sh --<mode> --yes` as the remote command**, not `mise bootstrap` directly — bootstrap.sh is what relocates the checkout, installs mise, exports `MISE_ENV`, and initialises chezmoi; `mise bootstrap` alone would skip all of that.
9. **Dozzle's old systemd unit is retired in the native `post-packages` task, BEFORE the compose phase runs** — not in an end-of-run sweep. Retiring it too late lets the old `docker run --name dozzle` container hold the compose project's port and name; verified as a real failure during the migration.

**Host state mechanics, quick reference:** dnf packages install as ONE `sudo dnf install -y <every missing name>` batch per `[bootstrap.packages]` table — **all-or-nothing**, unlike the old Make-era per-package `|| true` fail-soft, so every name is EL9-verified (2026-09-17 spike against AlmaLinux 9.8). Dozzle is now a `docker compose` project (`[bootstrap.compose.dozzle]`, `configs/dozzle/compose.yaml.tera`, Tera-rendered — the old sed-substituted `dozzle.env` is gone). `[bootstrap.files]` `source` paths are relative to the repo root; `phase` is only `pre-packages`/`post-packages`; no `sudo` key (mise elevates itself).

**Pins Make owned directly move to `config.toml`'s `[vars]`, renamed:** `python_version` (was `PYTHON_VERSION`), `nerd_font_version` (was `JETBRAINSMONO_NERD_VERSION`), `dozzle_version` (was `DOZZLE_VERSION`), `vcpkg_version` (was `VCPKG_VERSION`), `zjstatus_zellij_floor` (was `ZJSTATUS_ZELLIJ_FLOOR`). `CLAUDE_VERSION` drops entirely — it was always `:= latest` (Claude Code self-updates, nothing to pin). Global tasks read `[vars]` via `#MISE env={NAME="{{ vars.name }}"}` headers (Tera rendering, spec-verified).

**Verification, read-only and safe with no sudo** (see Ruling 1 for why `plan`/`status` are safe even unprivileged): `MISE_ENV=<set> mise bootstrap plan --json | jq .summary`, `mise bootstrap status --missing`, `mise run health`, `mise tasks validate`, `systemctl --user cat dev.mise.pueued.service` (confirms no `Environment=` line — Ruling 6).

**Hard limits that held for this migration and likely hold for PR3 too:** never `sudo`; never `mise bootstrap` except `plan`/`status`/`--dry-run`; never `./bootstrap.sh --dev|--prod`, `chezmoi apply`, `mise lock`, or `mise install` from an agent — hand sudo-requiring proofs to the user.

PR1 (the tool layer — every tool a mise pin in `config.toml`/`config.linux.toml`/`config.dev.toml`, the repo root IS mise's global config dir, the four-part lock artifact set, `python` declared for `pypi:` lockfile solving) is unchanged by this PR and still holds; see `[[project-mise-runtimes-shipped]]` for the Windows-interop-probe gotchas that still apply verbatim (UNC cwd walks, winget long-path uninstall failures, PS 5.1 vs pwsh 7 `Sort-Object` ordering) — relevant again once PR3 brings `mise bootstrap` to Windows.
