All three PRs of the Make→mise migration (spec `docs/superpowers/specs/2026-09-16-mise-everything-design.md`) are merged — #155 (PR1), #156 (PR2), #157 (PR3, squash-merged 2026-09-23 as 28d2c84; `feat/mise-dotfiles` deleted). **Still open after the merge (user/network-only):** first run on the native dev host `atc-cache-dev10`, then one prod host followed by the prod group via `scripts/update-hosts.sh`. The Windows node-lock fallback in `Invoke-MiseRuntimes` remains unexercised (triggers only under a live lock). **Both legacy systems are fully gone: there is no Makefile anywhere in this repo, and there is no chezmoi anywhere in this repo.** PR1 put every tool on a mise pin and made the checkout mise's own global config dir; PR2 moved every piece of host state (dnf packages, EPEL/CRB enablement, `/etc` files, docker/dozzle/cockpit/rsyslog services, `/etc/wsl.conf`, the pueued user service, and the doctor/check-updates/lint/fmt/secrets/install-hooks/python-env/fonts/vcpkg/statusline utilities) into `[bootstrap.*]` tables and global mise tasks; PR3 moved every dotfile chezmoi used to deploy to `$HOME` (Linux and the one Windows host) into mise's own `[dotfiles]` feature, deleted `chezmoi/`, `.chezmoiroot`, the chezmoi and chezit tools, and renamed the `cz*` shell aliases to `ws*`.

**`[dotfiles]`, mode per class (as of the 2026-09-22 copy migration — SUPERSEDES the PR3-era symlink model below):** each target is one entry, keyed by the target path (`"~/.zshrc"`), `source =` a real filename under `dotfiles/` (git-mv'd from `chezmoi/**`, no more `dot_`/`private_` prefixing), declared in whichever `config*.toml` file the `MISE_ENV` token gates. Two modes total, everywhere: `template` — 11 `.tera` sources (Tera templating). `copy` — literally everything else (47 entries total) — app-rewritten files (Warp/Windows Terminal/Zed/VS Code, every Windows entry) AND everything that used to be `symlink`/`symlink-each`. A directory source keeps `exclude = [".vendor", ".gitkeep"]` on its `copy` entry exactly as it did under `symlink-each` — re-verified that `copy` on a directory does NOT wholesale-replace it (unmanaged siblings survive). **`symlink`/`symlink-each` are RETIRED, on every platform** — this was PR3's "big behavioral change" (a symlinked target lived INSIDE the checkout, so editing it dirtied the repo); that's gone now. A deployed file is an independent copy under `$HOME`: editing it does NOT dirty the repo, but it also does NOT round-trip back to `dotfiles/` on its own any more. `wsr` (`mise dot add --changed`) captures a FILE-mode entry's edit; it SKIPS directory-mode entries entirely — the only way to round-trip one of those (`~/.claude/agents`, `~/.claude/commands`, `~/.claude/hooks`, `~/.claude/skills`, `~/.config/zellij`, `~/.config/zsh/completions`, `~/.config/gdb`, `~/.local/bin`) is `mise dot add <dir>` naming the directory's own exact target path — which captures edits AND new files in one shot but REPLACES the source directory (drops a source-only `.gitkeep`). Also: **copy-mode `mise dot apply` silently overwrites an un-recorded live edit** (no `--force`, no diff, no warning) — `wsa` is now a function that checks `mise dot status --json` for `differs`-state entries first and asks before proceeding, closing that gap for the interactive alias (a bare `mise bootstrap --only dotfiles --yes` still overwrites silently, by design).

**New/changed config surface:** `config.windows.toml` (new — the 13 Windows-only dotfiles, `windows` token) joins `config.toml`/`config.linux.toml`/`config.dev.toml`/`config.host.toml` (all of which now also carry `[dotfiles]` tables, not just `[bootstrap.*]`) in the token-gated file set. `config.local.toml` (git-ignored, per-host) still carries `[vars] name`/`email`, written once by `bootstrap.sh`'s `ensure_config_local()` (migrates from a legacy `~/.config/chezmoi/chezmoi.toml` if present, else prompts via `/dev/tty`), plus any per-host `[dotfiles]` override (e.g. the ccstatusline opt-out `scripts/setup-ccstatusline.sh` writes).

**The ten Rulings** (verified-fact deviations from the original spec, binding across all three PRs — 1, 2, 5, 6, 7, 9, 10 are PR3-specific; 3, 4, 8 below are numbered per the PR3 plan and restate/supersede the PR2 Rulings list where they overlap):
1. **First apply on every host that ran the old chezmoi bootstrap needs `--force-dotfiles`.** `symlink`/`symlink-each` refuse a pre-existing real file (even `--dry-run` exits 1: `mise ERROR files: refusing to overwrite existing files (use --force)`) — every target IS one today, since chezmoi already deployed it. `bootstrap.sh`/`bootstrap.ps1` pass `--force-dotfiles` automatically, but ONLY while `~/.local/state/workstation/dotfiles-migrated` is absent, so a later real conflict still fails loudly.
2. **There is no `state = "absent"` key.** Disabling an inherited `[dotfiles]` entry needs `enabled = false` AND a repeated `mode` in the overriding file — `enabled = false` alone is silently ignored. The per-host ccstatusline opt-out (in `config.local.toml`) works exactly this way.
3. **One broken template aborts the WHOLE apply and writes NOTHING at all.** An undefined Tera `vars.*` reference or a failing `exec()` in ANY `mode = "template"` entry fails the entire `mise dot apply`/`mise bootstrap` run — not just that one entry. `scripts/check-templates.sh` was rebuilt around this: it applies + syntax-checks every template INDIVIDUALLY (for all four real `MISE_ENV` sets) before any bulk apply, so a failure names the exact culprit instead of a useless bulk-run error.
4. **Hostname/kernel/git-identity have no native Tera functions** — they're `exec(command="hostname")` / `exec(command="uname -r")` / `exec(command="git config --get user.name")`. Since ruling 3 means a failing `exec()` aborts everything, every `exec()` used in a template must be a command that can't fail on a bare host, or must be wrapped with a fallback.
5. **`~/.claude/settings.json` is NOT a `[dotfiles]` entry at all** — mise has no `modify_`-template equivalent for a merge-on-apply file. `scripts/lib/claude-settings-merge.sh` (jq), invoked from `tasks/bootstrap` and dev-gated, does the three-layer deep merge instead: `dotfiles/claude/settings.seed.json` (set-if-absent) → the live file → `dotfiles/claude/settings.enforced.json` (always wins). `settings.local.json` also stays untracked — Claude Code rewrites it wholesale.
6. **No `run_onchange_*` equivalent exists.** The old `.wslconfig`-changed "run `wsl --shutdown`" reminder moves into `bootstrap.ps1` as a sha256-marker step, the same mechanism it already used for other files.
7. **Every entry is `copy`, never `symlink`, anywhere — broadened 2026-09-22 from "Windows only" to everywhere, by explicit user decision (chezmoi's copy semantics survive apps that don't respect symlinks).** File symlinks need Developer Mode on Windows and silently fall back to copying anyway; `symlink-each` always copied on Windows; a directory symlink becomes a junction there. `copy` makes the behavior identical everywhere and is exactly what `mise dot add --changed` (`wsr`) round-trips FOR A FILE ENTRY — it skips directory entries; those need `mise dot add <dir>` instead (see the mode-per-class paragraph above).
8. **RETIRED 2026-09-22.** Used to read: "Symlinked dotfiles live inside the git checkout, so editing one dirties the repo and `update-hosts.sh`'s `git pull --ff-only` then fails against local changes." Since every entry is `copy`/`template` now, a deployed file is an independent copy under `$HOME`, not a symlink into the checkout — editing one no longer dirties the repo, full stop. What replaces the concern: a live edit no longer round-trips implicitly either (see the mode-per-class paragraph above), and copy-mode `mise dot apply` silently overwrites an un-recorded live edit with no warning — `wsa` now checks for drift first. `mise run health`'s "repo checkout" row still exists (the repo CAN still go dirty — a hand-edited pin, `wse`, or a `wsr`/`mise dot add` write to a source file under `dotfiles/`) but no longer for the symlink reason.
9. **age/encryption was dropped, not ported.** Zero `encrypted_*` files ever existed and no host had a `key.txt`; `bootstrap.sh`'s old `check_age_identity`/`WORKSTATION_AGE_RECIPIENT` plumbing is gone entirely. `secret-guard.sh` keeps a defensive check for a leftover `chezmoi/key.txt` purely in case one still lingers on an unmigrated host.
10. **The dev-gate asymmetry chezmoi had is fixed by construction.** chezmoi's old ignore block listed only Linux-form target paths for the dev-only gate, so a hypothetical Windows prod host would have deployed `~/.claude` ungated. Dev-only dotfiles now live in `config.dev.toml`/`config.host.toml`, gated purely by the `dev`/`host` `MISE_ENV` tokens on BOTH OSes — symmetric by construction, no separate ignore-list to fall out of sync.

**Daily workflow, `cz*` → `ws*` (all four shells: bash, zsh, PowerShell, Nushell):** `wsa` = apply, but (2026-09-22) now a FUNCTION that checks `mise dot status --json` for un-recorded drift first, shows `mise dot diff`, and asks before overwriting (plain `mise bootstrap --only dotfiles --yes` is still the raw silent-overwrite form) · `wsd` = `mise dot diff` · `wss` = `mise dot status` · `wse <path>` = `mise dot edit` (opens the source-state copy) · `wsr` = `mise dot add --changed` (record a FILE entry's edit back to source — SKIPS directory entries; use `mise dot add <dir>` for those, e.g. `~/.claude/agents`) · `wsu` = `mise run update` (`git pull` + `mise install` + `mise bootstrap`) · `wsh` = the cheat sheet (bash/zsh only — no Windows equivalent). `czt`/chezit (the TUI) has no replacement; it's just gone.

**`bootstrap.ps1` changes:** chezmoi itself is no longer installed (dropped from `$PortableTools`) — it's only still mentioned in a one-time leftover-config sweep (`Remove-Item %USERPROFILE%\.config\chezmoi` if present) and the legacy-checkout-relocation logic, neither of which touches the chezmoi binary. `Invoke-MiseBootstrap` runs `mise bootstrap --only dotfiles,tools --yes` in one pass (dotfiles apply + a tools pass together); `Invoke-MiseRuntimes` then re-runs to self-heal the shims-dir PATH entry. `-SkipChezmoi` is renamed `-SkipDotfiles`.

**A measured mise behavior worth knowing (verified 2026-09-19, mise 2026.9.9):** global-config discovery honours a `HOME=` override ONLY when that home already has its own `.config/mise` — otherwise it FALLS BACK to the real account home's config. On every real host the account home already IS the checkout, so `HOME=<scratch>` "just works" by accident; in CI (account home ≠ checkout) it silently reads the wrong config instead of erroring, so a scratch-`HOME` apply/render can appear to succeed while writing nothing meaningful. `scripts/check-templates.sh`'s header documents this and works around it with an additive-only symlink at the real account home (removed again on exit) — mirror that pattern rather than re-deriving it.

**RESOLVED — the `vars.group` wiring gap (found in PR3 Task 7):** the three `MISE_ENV`-baking templates gate on `vars.group == "dev_machine"`, but nothing wrote `vars.group`, so every host baked prod-only `MISE_ENV="linux"` into new shells. Fixed in 53bdc96: `bootstrap.sh`'s `ensure_config_local()` now writes `group` into `config.local.toml` (and `repair_config_local_group` backfills it on existing hosts). If a new login shell on a dev host ever shows `MISE_ENV=linux`, check `config.local.toml` for `group` first.

**Verification, read-only and safe with no sudo:** `mise dot status`/`mise dot diff` (`wss`/`wsd`), `bash scripts/check-templates.sh` (renders + syntax-checks every template for all four MISE_ENV sets, individually then bulk), `mise dot apply --force --yes -- "<target>"` against a SCRATCH `$HOME` only (never the real one), `MISE_ENV=<set> mise bootstrap plan --json | jq .summary`, `mise bootstrap status --missing`, `mise run health` (now has dotfiles-drift and dirty-checkout rows), `mise tasks validate`.

**Hard limits:** never `sudo`; never `./bootstrap.sh`; never `mise dot apply`/`mise bootstrap --only dotfiles` (or any bulk `mise bootstrap`) against the real `$HOME` from an agent — a review agent did this by accident once and overwrote two live files. Scratch `$HOME`s under `/tmp` only for any dotfiles apply/render testing.

**Legacy detail that still applies verbatim** (from PR1/PR2, unchanged by PR3): the four-part lock artifact set (`mise.lock`/`mise.linux.lock`/`mise.dev.lock` + `locks/**`), `python` declared in `config.toml` for `pypi:` lockfile solving, the nine PR2 host-state Rulings (no `[bootstrap.linux.firewall]` table, no `[bootstrap.user] login_shell`, vcpkg stays a task not `[bootstrap.repos]`, hooks are always `mise run <task>` [with `post-dotfiles` now the one pinned-literal exception, PR3], `make` stays in the dnf list, pueued's `MISE_ENV` from the user manager not the unit, `mise-install.sh` before `mise bootstrap`, `update-hosts.sh` keeps `./bootstrap.sh --<mode> --yes` as the remote command, Dozzle's old unit retired before the compose phase — this last one is now purely historical, see below); see `[[project-mise-runtimes-shipped]]` for the Windows-interop-probe gotchas (UNC cwd walks, winget long-path uninstall failures, PS 5.1 vs pwsh 7 `Sort-Object` ordering) that still apply now that `mise bootstrap` runs on Windows too.

**2026-09-22: Docker/Cockpit/rsyslog/Dozzle provisioning removed entirely (user decision, separate from the Make→mise migration above).** Everything PR2 gave `config.native.toml` beyond the NFS client packages — the Docker CE repo + packages + service, the Cockpit packages + `cockpit.socket` + firewalld hook, the rsyslog drop-in + service, and the Dozzle `docker compose` project (`configs/dozzle/compose.yaml.tera`, plus the `native-post-packages` hook that retired the old Make-era `dozzle.service` unit) — is deleted: `tasks/native-post-packages` and `configs/{docker,cockpit,rsyslog,dozzle}/` are gone, `config.native.toml` is NFS-client-only, `dozzle_version` is gone from `config.toml`'s `[vars]`. **This is a config-removal, not a sweep** — the three native dev hosts that already carry the Make-era docker/cockpit/rsyslog/dozzle state keep it, running and unmanaged; nothing here uninstalls or updates it any more.
