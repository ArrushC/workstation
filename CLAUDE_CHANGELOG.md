| Restored CTRL+click → `OpenLinkAtMouseCursor` as an explicit `mouse_bindings` entry in `chezmoi/dot_config/wezterm/wezterm.lua` to actually wire the previous commit's `open-uri` handler into the click chain. The existing no-mods override (plain `CompleteSelection` + `copy_and_announce` for the "Copied!" badge) displaced that composite default, removing the link-open fallthrough that the original CTRL+click UX silently depended on. **There is NO default `mods=CTRL` binding for `OpenLinkAtMouseCursor`** — the `wezterm.org/config/mouse.html` page lists one but it's a docs bug; the source at `wezterm-gui/src/inputmap.rs` and the `wezterm.org/recipes/hyperlinks.html` recipe agree there isn't. Restating CTRL+click explicitly re-introduces the link-open path on the modified-click variant without giving up the copy-on-release UX from the no-mods override. CTRL+SHIFT+click kept working through this whole episode because the separate `mods=SHIFT` default (also composite) was never displaced.
